# Продукт: концепция и границы MVP

> Обновлено: 2026-07-31 · Статус: согласовано · Источник: ТЗ §1–7, §25

## Концепция

Приложение сопровождает игрока через полный сценарий применения заклинания, а не показывает справку:

1. Помочь выбрать подходящее заклинание.
2. Проверить возможность его использования.
3. Объяснить, что должен сделать игрок.
4. Подготовить короткую формулировку для мастера.
5. Подсказать реплику и визуальное описание для отыгрыша.
6. Определить необходимые броски и спасброски.
7. Потратить ячейку заклинания.
8. Запустить концентрацию или другой активный эффект.
9. Напоминать о продолжающемся действии заклинания.

Основной принцип:

> Приложение не играет вместо пользователя, а помогает быстро и правильно применить магию и
> выразительно её отыграть.

## Проблема

Игрок за заклинателя имеет много доступных действий и мало времени на решение. Одновременно
приходится читать длинное описание, помнить правила действий и концентрации, считать ячейки,
определять спасброски, объяснять решение мастеру, придумывать художественное описание и отслеживать
активные эффекты. Это замедляет игру и снижает уверенность игрока.

Дополнительные болевые точки, которые продукт обязан снимать:

- полные тексты заклинаний неудобны для быстрого чтения в бою;
- игрок забывает о доступных реакциях, потому что они срабатывают не в его ход;
- игрок может случайно запустить второе заклинание с концентрацией;
- непонятно, кто делает бросок — игрок или мастер;
- непонятно, что именно меняется при использовании ячейки повышенного уровня;
- после применения игрок забывает о продолжающемся эффекте;
- художественный отыгрыш приходится придумывать во время собственного хода.

## Ниша

Продукт находится между справочником заклинаний и виртуальным игровым столом:
**интерактивный помощник по применению и отыгрышу магии.**

Существующие приложения решают либо задачу справочника, либо задачу полного листа персонажа, и почти
не помогают в момент боя.

## Аудитория

Игроки D&D 5e, играющие за магический класс, с большим числом заклинаний, испытывающие сложности с
быстрым применением правил, желающие лучше отыгрывать магию и использующие смартфон за столом.

### Первая персона

| Параметр | Значение |
|---|---|
| Игрок | Иван |
| Персонаж | Торн |
| Вид | лунный тролль (самодельная раса) |
| Класс и уровень | волшебник, 7 |
| Подкласс | Создатель рун |
| Интеллект | 18 |
| Подготовленных заклинаний | 11 |
| Заговоров | 4 |
| Стиль магии | руны, молнии, холод, алхимические символы |
| Стиль речи | короткие формулы, сарказм, самоуверенность |
| Ограничение | огонь отключает его расовые особенности |

Персонаж оказался сложнее типичного волшебника, и это меняет объём MVP: у него два источника магии
(ячейки и кровавое колдовство), два дополнительных расходуемых ресурса (руны, очки заклинаний), два
состояния подавления (огонь, солнце) и запрет мастера на часть заклинаний. Всё это перечислено в
[области MVP](#область-mvp).

Вывод для продукта: ниша «интерактивный помощник по применению магии» подтверждается на первом же
реальном персонаже. Ни один справочник и ни один лист персонажа не считает за игрока, сколько здоровья
стоит заклинание третьего уровня и работает ли эта способность после урона огнём.

Профиль отыгрыша Торна в машинном виде хранится вместе с контентом заклинаний.

## Цели MVP

Приложение должно сокращать время применения заклинания, снижать число ошибок в правилах, помогать
объявлять действия мастеру, помогать отыгрывать магию, автоматически отслеживать ячейки и
концентрацию, работать без интернета, быть удобным на экране iPhone и поддерживать
персонализированный стиль конкретного персонажа.

## Метрики

Проверяются после тестовой игровой сессии. Способ измерения — локальный сбор событий
(см. [constraints.md](constraints.md#локальная-аналитика)), данные не покидают устройство.

| ID | Метрика | Целевое значение |
|---|---|---|
| M-01 | Время от открытия приложения до нужного заклинания | ≤ 5 с |
| M-02 | Число нажатий до технической инструкции | ≤ 2 |
| M-03 | Число шагов на применение заклинания | ≤ 4 основных |
| M-04 | Ручное списание ячеек | отсутствует, списание автоматическое |
| M-05 | Незамеченный запуск второй концентрации | невозможен |
| M-06 | Видимость активного эффекта после закрытия карточки | сохраняется |
| M-07 | Сохранность данных после перезапуска | 100 % |
| M-08 | Работоспособность без интернета | полная |

## Область MVP

**Граница одна: MVP — про магию Торна в бою.** Входит то, без чего нельзя выбрать заклинание,
проверить условия, оплатить, объявить, отыграть и отследить его до конца. Всё остальное — вне
области, и это правило, а не список: список пришлось бы дописывать на каждое предложение.

Из этой границы следует состав: один персонаж, его книга и ячейки, подготовка, фильтрация,
пошаговое применение, инструкции мастеру и реплики персонажа, концентрация и активные эффекты,
реакции, отдых и восстановление, локальное хранение с выгрузкой. Разбор настоящего персонажа добавил
руны подкласса, запреты мастера и вида, кровавое колдовство как второй источник магии и подавление
особенностей огнём и солнцем.

Две границы объяснены отдельно, потому что о них спрашивают: кубики бросает игрок
([OQ-09](open-questions.md#oq-09)), длительность эффектов отсчитывает стол
([constraints.md](constraints.md#после-mvp)).

## Итоговое определение MVP

MVP — это устанавливаемое офлайн-приложение для iPhone, которое содержит магию Торна и помогает во
время боя выбрать заклинание, проверить условия, правильно объявить действие, красиво его отыграть,
определить броски, потратить ячейку, запустить и отслеживать эффект, контролировать концентрацию и
реакции.

Формальная проверка готовности — 20 критериев в [quality.md](quality.md#критерии-приёмки-mvp).
