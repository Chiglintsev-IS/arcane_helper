# Одна реплика и схема ритуала

> Дата: 2026-07-31 · Ветка: feature/combat-vertical-slice

Две независимые части. Первая исправляет то, как выглядит художественный текст в карточке. Вторая
добавляет новую фичу — рисунок ритуала, который игрок повторяет на листе А4.

Части не зависят друг от друга и могут делаться в любом порядке, но обе трогают файлы контента
заклинаний, поэтому делаются подряд, чтобы не переписывать одни и те же двенадцать JSON дважды.

## Часть 1 — одна реплика на заклинание

### Проблема

Карточка показывает `Стой на месте. · Холодно.` Это не одна реплика, а весь массив реплик, склеенный
через ` · ` в [RoleplaySection.tsx](../../../src/components/spell/RoleplaySection.tsx). У всех
двенадцати заклинаний в контенте лежит ровно по две альтернативные реплики, и обе показываются
одновременно, как будто персонаж произносит их подряд. Рядом тем же способом выводится жест — блок
отыгрыша распадается на обрывки вместо одной фразы, которую можно сразу сыграть.

Массив, у которого никогда не бывает второго осмысленного применения, — источник этой склейки.
Убираем массив, а не склейку.

### Решение

Три поля профиля отыгрыша становятся единственного числа:

| Было | Стало |
|---|---|
| `roleplay.incantations: string[]` | `roleplay.incantation: string` |
| `roleplay.gestures: string[]` | `roleplay.gesture: string` |
| `roleplay.visualEffects: string[]` | `roleplay.visualEffect: string` |

Во всех двенадцати файлах контента в `gestures` и `visualEffects` уже лежит ровно по одному элементу,
поэтому там правка механическая. Разнообразие остаётся там, где оно осмысленно: в трёх категориях
полных вариантов отыгрыша (`completeVariants`), которые и задуманы как выбор.

`completeVariants` остаётся массивами: категория может содержать несколько вариантов, между ними
предусмотрена ротация.

### Контент: какая из двух реплик остаётся

Правило выбора: остаётся та, что несёт механику заклинания, а не комментарий к ней. «Стой на месте»
говорит про снижение скорости, «Холодно» не говорит ни о чём.

| Заклинание | Остаётся | Уходит |
|---|---|---|
| Луч холода | «Стой на месте.» | «Холодно.» |
| Электрошок | «Заземления не будет.» | «Держи.» |
| Починка | «Как было.» | «Соберись.» |
| Послание | «Слушай.» | «Только ты.» |
| Щит | «Нет.» | «Не сегодня.» |
| Поглощение стихий | «Мне пригодится.» | «Спасибо.» |
| Доспехи мага | «Так надёжнее.» | «Кожа выдержит.» |
| Маскировка | «Другое лицо.» | «Так удобнее.» |
| Обнаружение магии | «Покажи.» | «Что здесь было.» |
| Опознание | «Рассказывай.» | «Кто тебя делал.» |
| Незримый слуга | «Работай.» | «Не мне же это делать.» |
| Поиск фамильяра | «Иди сюда.» | «Ты мне нужен.» |

Удалённые реплики не переезжают в другие поля: короткая фраза, которая никому не показывается, —
мёртвый контент.

### Интерфейс

В блоке отыгрыша вместо `dl` со склейкой — две подписанные строки:

```
Реплика   «Стой на месте.»
Жест      Ведёт указательным пальцем короткую прямую руну в воздухе.
```

Реплика показывается в кавычках-ёлочках: это прямая речь, и кавычки отличают её от описания жеста.
`visualEffect` в карточке по-прежнему не показывается — он остаётся в данных, потому что его требует
[FR-050](../../features/F-04-roleplay.md#fr-050), и эта работа его судьбу не меняет.

### Правки спеки

[FR-050](../../features/F-04-roleplay.md#fr-050) сейчас требует «минимум одну короткую реплику;
минимум одно описание жестов; минимум одно описание визуального эффекта». Переформулируется в «ровно
одну». Без этого код с единственным числом не следует ни из одного требования — то есть нарушает
правило «нет требования — нет фичи» из CLAUDE.md.

Минимум трёх полных вариантов отыгрыша в том же требовании остаётся без изменений.

### Проверка

| Что | Как |
|---|---|
| Схема отвергает массив в `incantation` | Unit на `spellSchema` |
| Все двенадцать файлов контента проходят схему | Существующий `content.test.ts` |
| Карточка показывает одну реплику без разделителя `·` | Компонентный тест на `RoleplaySection` |
| Длина реплики в пределах `maximumPhraseLength` | Существующая проверка контента |

## Часть 2 — схема ритуала (новая фича F-17)

### Зачем

У ритуала есть то, чего нет у боевого заклинания: время. Десять лишних минут по правилам — это
десять минут за столом, которые нечем занять. Игрок хочет занять их рисованием: взять лист А4 и
повторить схему ритуала рукой. Тогда «сотворить ритуал» перестаёт быть словами в объявлении мастеру и
становится тем, что игрок действительно делает.

Требование к рисунку сформулировал игрок: сложный, тематический, с духом магических книг. И при этом
воспроизводимый рукой — иначе смысл теряется.

### Принцип: слои, а не свободный рисунок

Круги в настоящих гримуарах — Агриппа, «Ключ Соломона», алхимические таблицы — собраны из
повторяющихся элементов: концентрические кольца, надпись по обводу, вписанная звезда, знаки на её
вершинах, печать в центре, числовой квадрат. Именно поэтому их рисовали циркулем и линейкой, и именно
поэтому они выглядят сложными: сложность там от количества слоёв, а не от свободы линии.

Из этого следуют оба нужных нам свойства сразу. Схема, собранная из слоёв, рисуется рукой (все
элементы — окружности, прямые и повторяющиеся знаки) и при этом получается плотной. Свободный
рисунок дал бы плотность, но повторить его на бумаге невозможно, а проверить в ревью — тем более.

Побочная выгода: описание слоёв — это же и порядок рисования. Схема из данных читается как
инструкция «сначала внешнее кольцо, потом деления, потом надпись».

### Модель данных

`ritualDiagram` — необязательное поле заклинания. Инвариант: есть у каждого заклинания с
`ritual: true` и отсутствует у остальных. Проверяется в `superRefine` рядом с существующей проверкой
«заговор не может быть ритуальным».

Система координат: `viewBox="0 0 1000 1000"`, центр `(500, 500)`, внешний радиус 460 единиц —
остаток отдан угловым знакам вне круга. Все радиусы в данных — доли внешнего радиуса, число в
диапазоне (0, 1].

```ts
// Доля внешнего радиуса: 1 — само внешнее кольцо, 0 — центр.
const radius = z.number().gt(0).max(1);

// Закрытый словарь знаков, состав — ниже.
const glyphId = z.enum(GLYPH_IDS);

const ritualDiagramSchema = z.object({
  // Концентрические кольца, снаружи внутрь. Первое всегда 1.
  rings: z.array(radius).min(2).max(4),

  // Деления по обводу, как на астрологической карте.
  tickRing: z.object({ count: z.union([z.literal(36), z.literal(72)]), radius }).optional(),

  // Надпись рунами по кругу между двумя кольцами.
  inscription: z.object({ runes: nonEmpty, meaningRu: nonEmpty, radius }).optional(),

  // Вписанная звезда: {points}/{skip} в нотации звёздчатых многоугольников.
  star: z.object({
    points: z.number().int().min(5).max(12),
    skip: z.number().int().min(2),
    radius,
  }).optional(),

  // Знаки на вершинах звезды либо равномерно по кругу, если звезды нет.
  radialGlyphs: z.object({ glyphs: z.array(glyphId).min(3), radius }).optional(),

  // Оси, делящие круг на секторы.
  crossAxes: z.object({ count: z.number().int().min(2).max(8), radius }).optional(),

  // Числовой квадрат 3×3 в духе таблиц Агриппы.
  magicSquare: z.object({ rows: z.array(z.array(z.number().int().positive())) }).optional(),

  // Печать в центре — единственный обязательный смысловой слой.
  centralSeal: z.object({
    kind: z.enum(["eye", "sphere", "summoning-triangle", "empty-hand"]),
    radius,
  }),

  // Четыре знака вне круга, по углам листа.
  cornerMarks: z.array(glyphId).length(4).optional(),

  // Что это за схема — для чтения, не для рисования.
  captionRu: nonEmpty,
});
```

Проверки, которые схема выполняет помимо типов:

- `rings` строго убывают, первое равно 1. Иначе кольца совпадают или выворачиваются наизнанку.
- радиус любого слоя не больше 1 — ничего не вылезает за внешнее кольцо, кроме `cornerMarks`.
- `star.skip < points / 2`. При `skip ≥ points / 2` фигура повторяет уже нарисованную.
- если есть и `star`, и `radialGlyphs` с тем же радиусом — число знаков равно `star.points`: знаки
  стоят на вершинах, и лишний знак некуда поставить.
- `magicSquare.rows` — три строки по три числа, и все строки, столбцы и обе диагонали дают одну сумму.
  Квадрат, который не магический, — ошибка контента, а не стиль.
- каждый символ `inscription.runes` есть в таблице рун; каждый `glyphId` есть в реестре глифов.

`glyphId` — закрытый словарь. Начальный состав: семь металлов алхимии (`sun`, `moon`, `mercury`,
`venus`, `mars`, `jupiter`, `saturn`), стихии без огня (`air`, `water`, `earth`, `lightning`, `frost`)
и двадцать четыре руны старшего футарка (`rune-fehu`…`rune-dagaz`). Огня нет, потому что его нет у
персонажа ([FR-052](../../features/F-04-roleplay.md#fr-052)).

Руны и глифы рисуются собственными путями, а не текстом Unicode: шрифта с рунным блоком на iPhone
может не оказаться, а схема должна выглядеть одинаково всегда — по ней рисуют. В JSON надпись хранится
настоящими символами рун, чтобы её можно было прочитать в ревью, а таблица переводит символ в путь.
Поле `meaningRu` рядом — что надпись значит; без него содержание надписи невозможно вычитать.

Религиозных имён и формул в надписях нет: словарь персонажа — руны и алхимия
([FR-052](../../features/F-04-roleplay.md#fr-052)), этого достаточно, чтобы схема была насыщенной.

### Четыре схемы

Тематика привязана к самому заклинанию, а не выбрана за красоту.

**Опознание.** Вопрос «из чего ты сделан» — алхимический вопрос, и в алхимии на него отвечают семь
металлов.

- `rings` 1, 0.92, 0.60 · `tickRing` 72 на 0.96
- `inscription` на 0.94: «расскажи чьими руками», руны
- `star` 7/3 на 0.58 — гептаграмма, семь вершин под семь металлов
- `radialGlyphs` на 0.58: `saturn`, `jupiter`, `mars`, `sun`, `venus`, `mercury`, `moon`
- `magicSquare` — квадрат Сатурна: `4 9 2 / 3 5 7 / 8 1 6`
- `centralSeal` `eye` на 0.30

**Обнаружение магии.** Сфера 30 футов, расходящаяся от заклинателя волной.

- `rings` 1, 0.86, 0.70, 0.54 — четыре кольца-волны · `tickRing` 36 на 0.93
- `inscription` на 0.95: «покажи»
- `star` 8/3 на 0.66 · `radialGlyphs` — восемь рун на вершинах
- `crossAxes` 4 на 0.86
- `centralSeal` `sphere` на 0.34

**Поиск фамильяра.** Круг вызова: тройное кольцо, стороны света, материальный компонент внутри
треугольника.

- `rings` 1, 0.93, 0.86 · `inscription` на 0.895: «иди сюда»
- `star` 6/2 на 0.72 — гексаграмма, две наложенные триады
- `crossAxes` 4 на 0.86
- `cornerMarks` `air`, `water`, `earth`, `lightning`
- `centralSeal` `summoning-triangle` на 0.44 — в него кладутся уголь и травы за 10 зм
- `captionRu` называет место под компонент: схема должна объяснять, зачем в центре пусто

**Незримый слуга.** Слуга незрим — центр демонстративно пуст.

- `rings` 1, 0.72 · `tickRing` 36 на 0.94
- `crossAxes` 4 на 0.72 — четыре сектора поручений
- `radialGlyphs` — четыре руны на осях
- `centralSeal` `empty-hand` на 0.40 — контур руки пунктиром, ничего внутри

`captionRu` у каждой из четырёх пишется при реализации — одна строка о том, что на схеме и зачем.
Здесь заданы слои, а не текст: текст вычитывается отдельно, как и остальной художественный контент.

Гексаграмма 6/2 — составная фигура: `НОД(6, 2) = 2`, поэтому рисуется двумя треугольниками, а не
одним обходом. Гептаграмма 7/3 и октаграмма 8/3 — единым обходом. Отрисовка обязана уметь оба случая,
и оба проверяются тестом.

### Отрисовка и модуль

Чистая часть — геометрия и таблицы путей — живёт в `src/diagram/`: вершины звёздчатого многоугольника,
положения делений, положение и поворот каждой руны надписи, пути глифов. React там нет.

Каталог добавляется в список покрытия `vitest.config.ts` рядом с движком правил: это вычисления, а не
разметка, и ошибка в них выглядит как испорченная схема, которую игрок будет перерисовывать.

Компонент `src/components/ritual/RitualDiagram.tsx` собирает `<svg>` по описанию: слой на функцию,
порядок отрисовки — порядок рисования на бумаге. Цвет — `currentColor`, чтобы схема работала в обеих
темах. Заливок нет, только штрихи: рисунок должен быть повторим пером.

### Интерфейс

Полноэкранный вид `RitualDiagramView`: `role="dialog"`, `aria-label="Схема ритуала"`, название
заклинания заголовком, схема квадратом во всю ширину экрана, `captionRu` под ней, кнопка закрытия.
Прокрутки нет — на iPhone SE схема видна целиком, иначе рисовать по ней неудобно.

Вход в двух местах:

- подробная карточка заклинания — кнопка «Схема ритуала», только если у заклинания есть `ritualDiagram`;
- мастер применения — та же кнопка на шаге объявления, только при выбранном способе `ritual`
  (`CastMode` уже различает `ritual`).

Кнопки печати нет. Смысл в том, чтобы вести линию рукой, а печать этот смысл отменяет.

### Границы

Схема — художественный текст в смысле [ADR-0005](../../decisions.md#adr-0005): не влияет на механику,
не блокирует подтверждение применения, её можно не рисовать вовсе. Приложение не спрашивает, нарисовал
ли игрок схему, и не хранит этого.

Не входит в работу: схемы для неритуальных заклинаний, редактор схем, свои схемы пользователя, таймер
ритуала, пошаговая подсветка порядка рисования, печать и экспорт в PDF.

### Правки спеки

Новый файл `docs/features/F-17-ritual-diagram.md` с четырьмя требованиями:

- R-1. У каждого ритуального заклинания есть схема ритуала; у неритуального её нет.
- R-2. Схема хранится описанием слоёв из закрытого словаря и проверяется вместе с остальным контентом.
- R-3. Схема открывается на полный экран из карточки заклинания и из мастера применения в ритуальном
  режиме.
- R-4. Схема не влияет на механику и не является обязательным шагом применения.

Номера `FR-###` присваиваются при создании файла: скрипт проверки требует, чтобы упомянутое
требование было где-то определено, поэтому в этом документе номеров нет. Свободный диапазон на сегодня
начинается после `FR-184`.

### Проверка

| Что | Как |
|---|---|
| У ритуала есть схема, у неритуального заклинания её нет | Unit на `spellSchema`, оба направления |
| Кольца убывают, первое равно 1 | Unit |
| `skip ≥ points / 2` отвергается | Unit |
| Немагический квадрат отвергается | Unit |
| Неизвестная руна и неизвестный глиф отвергаются | Unit |
| Все четыре схемы контента валидны | Существующий `content.test.ts` |
| Звезда 7/3 — один обход, 6/2 — два треугольника | Unit на геометрии |
| Число делений и положения рун надписи | Unit на геометрии |
| Кнопка есть только у ритуального заклинания | Компонентный тест на карточке |
| Кнопка в мастере есть только при способе `ritual` | Компонентный тест на мастере |
| Схема видна целиком без прокрутки на 375 px | Ручная проверка на iPhone SE |
| Схему можно перерисовать на А4 за время ритуала | Игровая проверка, все четыре схемы |

Последняя строка — единственная настоящая проверка этой фичи: если рисунок не получается повторить
рукой или получается, но не радует, ни один unit об этом не скажет.
