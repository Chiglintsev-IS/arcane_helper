# Движок правил

> Обновлено: 2026-07-31 · Статус: согласовано · Источник: правила D&D 5e (2014), ТЗ §9

Все формулы и алгоритмы правил, применяемые приложением. Этот документ — единственный источник чисел
для кода: константы не дублируются в компонентах, а вычисляются функциями движка.

**Правила движка.** Чистые функции без побочных эффектов, без доступа к хранилищу и без React.
Каждая формула отсюда покрыта unit-тестом. Ни одна формула не изобретается: если правило неизвестно —
запись в [open-questions.md](open-questions.md), а не догадка в коде.

## Производные характеристики

Формулы этого раздела дают **значение по умолчанию**, а не окончательное. Предметы и черты сдвигают
итоговые числа: посох может добавить к КС спасброска, черта — дать владение спасброском Телосложения.
Поэтому `spellSaveDc`, `spellAttackModifier` и `constitutionSaveModifier` хранятся полями состояния
([domain-model.md](domain-model.md#состояние-персонажа)), а не вычисляются в месте использования.
Состав предметов Торна пока не зафиксирован — [OQ-11](open-questions.md#oq-11).

Практическое следствие для кода: функция считает базовое значение, состояние хранит фактическое, и
интерфейс показывает фактическое. Итоговые числа не прописываются константами.

### Бонус мастерства

```
proficiencyBonus(level) = 2 + floor((level - 1) / 4)
```

Для 7 уровня: `2 + floor(6/4) = 2 + 1 = +3`.

### Модификатор характеристики

```
abilityModifier(score) = floor((score - 10) / 2)
```

Интеллект 18 → `floor(8/2) = +4`.

### КС спасброска от заклинаний

```
spellSaveDc = 8 + proficiencyBonus + abilityModifier(intelligence)
```

Торн: `8 + 3 + 4 = 15`.

### Модификатор атаки заклинанием

```
spellAttackModifier = proficiencyBonus + abilityModifier(intelligence)
```

Торн: `3 + 4 = +7`.

### Лимит подготовки

Для волшебника:

```
preparedLimit = abilityModifier(intelligence) + wizardLevel
```

Торн: `4 + 7 = 11`. Заговоры в лимит не входят ([FR-102](features/F-09-preparation.md#fr-102)).

### Списание ячейки

```
Заговор (level = 0)          → ячейка не расходуется
Ритуальное применение        → ячейка не расходуется
Обычное применение           → расходуется ячейка выбранного уровня
```

Выбранный уровень не может быть ниже уровня заклинания. Может быть выше — это повышение уровня.

### Магическое восстановление

Особенность волшебника, один раз между долгими отдыхами, после короткого отдыха:

```
recoveryBudget = ceil(wizardLevel / 2)
```

Торн: `ceil(7/2) = 4`. Возвращаемые ячейки должны быть уровня 5 или ниже, суммарный уровень
возвращённых ячеек не превышает бюджет, и ни по одному уровню нельзя превысить максимум.

Пример допустимых наборов при бюджете 4: одна ячейка 4 уровня; ячейки 3 + 1; ячейки 2 + 2;
ячейки 2 + 1 + 1; четыре ячейки 1 уровня.

## Концентрация

### КС проверки концентрации

```
concentrationCheckDc(damage) = max(10, floor(damage / 2))
```

| Полученный урон | КС |
|---|---|
| 1 | 10 |
| 12 | 10 |
| 19 | 10 |
| 20 | 10 |
| 21 | 10 |
| 22 | 11 |
| 40 | 20 |

Округление вниз: при уроне 21 половина равна 10,5 → 10, что не превышает 10, поэтому КС остаётся 10.

Бросок — спасбросок Телосложения. Модификатор берётся из `constitutionSaveModifier` состояния
персонажа, а не вычисляется: волшебник не владеет этим спасброском по умолчанию, но черта может это
изменить. См. [OQ-05](open-questions.md#oq-05).

Каждый экземпляр урона требует отдельной проверки; урон за раунд не суммируется.

## Разрешение заклинания

Три взаимоисключающих способа (`resolution.type`):

| Способ | Кто бросает | Против чего |
|---|---|---|
| `spell_attack` | игрок | КД цели |
| `saving_throw` | цель (бросает мастер) | `spellSaveDc` персонажа |
| `automatic` | никто | эффект применяется без броска |

Приложение обязано явно указывать, кто бросает: это одна из перечисленных в
[product.md](product.md#проблема) болевых точек. «Волшебная стрела» — пример `automatic`: попадание
не бросается вовсе.

### Модификатор атаки не добавляется к урону

```
бросок атаки  = d20 + spellAttackModifier
урон          = формула заклинания, без модификатора характеристики
```

Урон заклинания — ровно то, что записано в `damage`, с учётом уровня ячейки или уровня персонажа.
Ни модификатор характеристики, ни бонус мастерства, ни бонус предмета в него не входят.

Путаница возникает из-за оружия: там модификатор характеристики прибавляется и к попаданию, и к
урону, а у заклинаний — только к попаданию. Ошибка тихая: числа выглядят правдоподобно, и урон
завышается каждый бой.

Практическое следствие для контента и кода: в `announcementTemplate` подстановки
`{spellAttackModifier}` и `{damage}` независимы, и вторая никогда не содержит первой. Предмет,
дающий бонус к магии, поднимает КС спасброска и бросок атаки, но не урон.

Исключения существуют (отдельные особенности классов прибавляют модификатор к урону конкретного
заклинания), но у Торна таких нет. Если появится — это данные заклинания, а не общее правило.

## Повышение уровня заклинания

Масштабирование хранится данными, а не кодом: `damage.scaling` — отображение «уровень ячейки → формула
урона», `higherLevelsRu` — текстовое описание для случаев, где меняется не урон (число целей,
длительность, размер области).

```
effectiveDamage(spell, slotLevel) = spell.damage.scaling[slotLevel] ?? spell.damage.dice
```

Пример — «Волшебная стрела»: `3d4+3` на 1 уровне, по одному дротику `1d4+1` за каждый уровень выше.
Результат подстановки попадает в объявление мастеру
([FR-041](features/F-03-cast-wizard.md#fr-041)).

Заговоры волшебника масштабируются от уровня персонажа, а не от ячейки: на 7 уровне «Луч холода»
наносит `2d8` (порог 5 уровня). Это отдельная ветка расчёта по уровню персонажа.

Кодирование в данных одно и то же поле `damage.scaling`, но ключи трактуются по-разному:

| Уровень заклинания | Смысл ключей `scaling` | Правило выбора |
|---|---|---|
| `level ≥ 1` | уровень израсходованной ячейки | точное совпадение ключа, иначе базовая формула |
| `level = 0` (заговор) | порог уровня персонажа | наибольший ключ, не превышающий уровень персонажа |

Пороги заговоров в 5e — уровни 5, 11 и 17. «Луч холода» на 7 уровне персонажа берёт ключ 5.

## Действия в ход

```
Одно действие, одно бонусное действие, одна реакция за раунд.
Реакция восстанавливается в начале своего хода.
```

Ограничение 5e «в один ход нельзя сотворить два заклинания, одно из которых требует ячейку, а
второе — бонусное действие» (правило бонусного действия) в MVP **не проверяется**: см.
[OQ-07](open-questions.md#oq-07).

## Отдых

| Отдых | Ячейки | Реакция | Концентрация | Магическое восстановление |
|---|---|---|---|---|
| Короткий (1 час) | не восстанавливаются | восстанавливается | снимается | доступно, если не использовано |

## Чего движок не делает

- не бросает кубики ([OQ-09](open-questions.md#oq-09));
- не отслеживает время и раунды автоматически ([F-08](features/F-08-active-effects.md));
- не хранит характеристики цели и не считает попадание;
- не применяет правила, не перечисленные в этом документе.

## Раса: лунный тролль

Самодельная раса из документа игрока. Числа не проверяемы по общедоступным правилам, поэтому
подтверждаются мастером — [OQ-15](open-questions.md#oq-15).

| Параметр | Значение |
|---|---|
| Размер | Большой |
| Скорость | 35 футов |
| Расовые очки здоровья | 11 |
| Тёмное зрение | 60 футов |
| Безоружная атака (бивни) | 1к4 колющий, от Силы |

Особенность «Закономерное мышление»: преимущество на проверки Интеллекта, связанные с
закономерностями, ритуалами, письменными договорами и последовательностями магических процессов;
помеха на проверки Проницательности об эмоциях, бескорыстии, абсурде и импровизации. На боевую магию
не влияет и в MVP не моделируется.

### Кровавое колдовство

Действием в свой ход хиты обмениваются на очки заклинаний. Курс зависит от ступени возвышения:

| Ступень (уровень) | Хитов за 1 очко |
|---|---|
| 1–4 | 2 |
| **5–8** | **3** |
| 9–12 | 4 |
| 13–16 | 5 |
| 17–20 | 6 |

Стоимость сотворения в очках заклинаний — **оспорена игроком**, см.
[OQ-15](open-questions.md#oq-15): ожидается «уровень 1 — 1 очко, уровень 2 — 2 очка», а приведённая
таблица совпадает с вариантом DMG. До ответа приложение считает по ней.

| Уровень заклинания | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| Очков | 2 | 3 | 5 | 6 | 7 |

```
hitPointCost(spellLevel, tierRate) = pointCost(spellLevel) × tierRate
```

Торн (7 уровень, курс 3): ячейка 1 уровня — 6 хитов, 2 уровня — 9, 3 уровня — 15, 4 уровня — 18.

Правила расхода:

- потеря хитов не считается получением урона и не требует проверки концентрации
  ([FR-174](features/F-15-blood-magic.md#fr-174));
- потраченные хиты снижают максимум здоровья; снижение не устраняется лечением, восстановлением,
  зельями и регенерацией;
- потеря, которая была уменьшена или предотвращена, очков не даёт;
- в временные хиты потеря не перенаправляется;
- обмен до нуля хитов даёт одну рану и ещё по одной за каждые три созданных очка;
- очки исчезают через час после создания;
- способность не действует под прямым солнечным светом и до конца следующего хода после урона огнём.

### Регенерация и восстановление

```
regenerationPerTurn(level) = 1 + floor(level / 3)
maximumRecoveryPerHour(level) = 1 + floor(level / 3)
```

Для 7 уровня обе величины равны 3.

Регенерация действует в начале своего хода при условиях: хитов больше нуля, текущее здоровье меньше
половины максимума (максимума с учётом снижения от кровавого колдовства), нет прямого солнечного
света, не получен урон огнём в течение прошлого хода.

Восстановление максимума происходит в конце каждого полного часа без солнечного света и без урона
огнём, не превышая величины, утраченной из-за кровавого колдовства.

### Солнечное проклятье

В MVP не отслеживается ([FR-184](features/F-16-troll-states.md#fr-184)), записано, чтобы не выяснять
заново.

```
sunSaveDc(savesMadeToday) = 10 + 2 × savesMadeToday
```

Спасбросок Телосложения в конце каждого часа под прямым солнечным светом после последнего долгого
отдыха. Провал добавляет стадию окаменения: первая — скорость вдвое меньше, вторая — состояние
«Опутан», третья — полное окаменение. Каждый полный час вне солнечного света снимает одну стадию
частичного окаменения; полное окаменение само не проходит.

Огонь подавляет особенности, но стадий окаменения не добавляет.
