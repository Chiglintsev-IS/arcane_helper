# F-11 — Импорт и экспорт

> Статус: Готово · Этап: 4 · Обновлено: 2026-08-01
> Требования: FR-120…FR-123 · Источник: ТЗ §17

## Зачем

Данные живут только в браузере одного устройства. Экспорт — единственный способ сделать резервную
копию, перенести персонажа на другое устройство и внести правки контента вручную. Он же — путь
наполнения приложения контентом на этапе 3.

## Требования

<a id="fr-120"></a>
### FR-120 — Состав экспорта

**Статус:** Готово · **Проверка:** unit `exportSnapshot (FR-120)`, [AC-19](../quality.md#критерии-приёмки-mvp)

Пользователь должен иметь возможность экспортировать: персонажа; заклинания; подготовленный набор;
профиль отыгрыша; текущее состояние ресурсов.

Формат экспорта — JSON.

Экспорт включает пользовательские дополнения: заметки к заклинаниям, собственные варианты отыгрыша,
отметки «любимое» и «отключено» ([FR-053](F-04-roleplay.md#fr-053)).

<a id="fr-121"></a>
### FR-121 — Проверка импорта

**Статус:** Готово · **Проверка:** unit `parseImport (FR-121)` на корректных и битых файлах

Импорт должен проверяться по JSON Schema.

Проверяется структура, типы, диапазоны (уровень 0–9, `remaining ≤ maximum`) и ссылочная целостность:
каждый идентификатор в подготовленном наборе существует в книге заклинаний.

<a id="fr-122"></a>
### FR-122 — Атомарность импорта

**Статус:** Готово · **Проверка:** компонентный `битый файл называет причину и состояние не трогает`

При ошибке импорта существующие данные не должны изменяться.

Атомарность распространяется на каталог заклинаний: персонаж и карточки заменяются одной записью
([FR-123](#fr-123)). Половины каталога не существует — приложение либо играет карточками из файла
целиком, либо не берёт из него ни одной.

<a id="fr-123"></a>
### FR-123 — Каталог заклинаний из импорта

**Статус:** Готово · **Проверка:** unit `каталог заклинаний (FR-123)` в сторе сессии; контракт
хранилища `каталог заклинаний переживает запись и чтение (FR-123)` и `запись без каталога читается:
играем встроенным (NFR-003)` — обе реализации порта проходят его одинаково

Карточки из импортированного файла должны стать теми, по которым играет приложение, и пережить
перезапуск.

Каталог хранится рядом с персонажем и меняется только вместе с ним, единственной точкой изменения
состояния ([ADR-0003](../decisions.md#adr-0003), [ADR-0019](../decisions.md#adr-0019)).

Отсутствие сохранённого каталога означает встроенный. Пока игрок не загрузил свой, каталог не
хранится вовсе, и обновление приложения продолжает приносить новые карточки.

Возврат к встроенному каталогу доступен всегда, когда он не разрушает состояние. Если заговоры,
книга или подготовленный набор персонажа ссылаются на карточку, которой во встроенном каталоге нет,
операция отклоняется и называет эту карточку — молча выбросить подготовленное заклинание нельзя.

Ссылочная целостность [FR-121](#fr-121) проверяется не только на входе файла, но и при каждой смене
каталога и при чтении сохранённого. После подмены каталога она перестала быть свойством файла и
стала инвариантом состояния: подготовленное заклинание без карточки — это строка, которую нечем
открыть.

## Поведение и крайние случаи

**Версионирование файла.** Экспорт содержит номер версии схемы. Импорт файла более новой версии
отклоняется с внятным сообщением, более старой — принимается с миграцией. Без версии в первом же
изменении структуры все ранее сделанные резервные копии станут нечитаемыми.

**Сообщение об ошибке по делу.** При провале проверки указывается путь до проблемного поля и что
именно не так. «Ошибка импорта» без деталей делает функцию бесполезной: пользователь правит JSON
руками.

**Импорт заменяет и персонажа, и каталог.** Карточки из файла становятся теми, по которым идёт игра,
и записываются рядом с персонажем одной операцией ([FR-123](#fr-123)). Второй режим импорта, «только
карточки», функция `applyImport` умеет, но входа в интерфейсе у него по-прежнему нет: он подменяет
каталог под неизменным персонажем, и целостность у него проверяется не против файла, а против уже
подготовленного набора — это отдельный экран с отдельным предупреждением, а не второе назначение той
же кнопки.

**Встроенный каталог — состояние по умолчанию, а не сохранённая копия.** Пока игрок не загрузил свой
файл, в хранилище карточек нет: приложение играет тем, что лежит в сборке. Копия встроенных карточек
в хранилище заморозила бы книгу на дате установки, и заклинание, добавленное следующей версией, не
появилось бы никогда ([ADR-0019](../decisions.md#adr-0019)).

**Чужой файл не отбирает карточки навсегда.** Возврат к встроенному каталогу — отдельная операция, а
не повторный импорт: файла, из которого можно было бы восстановиться, у игрока может не быть вовсе
([NFR-003](F-12-offline-pwa.md#nfr-003)). Возврат отклоняется, только если в состоянии остались
ссылки на карточки, которых во встроенном каталоге нет.

**Журнал начинается заново.** Записи прежнего персонажа к новому состоянию не относятся, и
«Отменить» после импорта вернуло бы ячейку тому, кого уже нет
([FR-111](F-10-journal-undo.md#fr-111)).

**Вход — в «Книге».** Резервную копию делают до игры, а не в бою: на боевом экране кнопка занимала бы
ряд ради задачи, которая случается раз в несколько сессий
([FR-203](F-18-screen-modes.md#fr-203)).

**Обмен файлами на iOS.** Экспорт — скачивание файла, импорт — выбор файла через системный диалог.
Работа с файлами в Safari на iOS ограничена, поэтому дополнительно поддерживается копирование JSON в
буфер обмена и вставка из него.

**Импорт как способ наполнения контентом.** Заклинания Торна вносятся правкой JSON в репозитории и
загружаются через тот же механизм проверки, что и пользовательский импорт: единая точка валидации
контента ([ADR-0004](../decisions.md#adr-0004)).

## Проверка

| Что проверяем | Как |
|---|---|
| Экспорт содержит все разделы FR-120 | Unit на снимке состояния |
| Импорт отклоняет битый, обрезанный и подменённый файл | Unit, набор фикстур |
| Провал импорта не меняет данные | Интеграционный: снимок до и после |
| Цикл экспорт → импорт даёт идентичное состояние | Property-based |
| Файл с неизвестной версией схемы отклоняется | Unit |
| Карточки из файла переживают перезапуск | Unit: второй стор на том же хранилище |
| Возврат к встроенному каталогу восстанавливает карточки сборки | Unit на сторе |
| Возврат, ломающий ссылки, отклоняется и называет карточку | Unit на сторе |
| Сохранение, сделанное до FR-123, читается со встроенным каталогом | Unit: запись без поля каталога |
