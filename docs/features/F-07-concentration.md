# F-07 — Концентрация

> Статус: План · Этап: 2 · Обновлено: 2026-07-31
> Требования: FR-080…FR-083 · Сценарии: [UC-03](../use-cases.md#uc-03), [UC-04](../use-cases.md#uc-04) · Источник: ТЗ §9.9

## Зачем

Случайно сброшенная концентрация — самая дорогая ошибка игрока-заклинателя: потерянная ячейка плюс
потерянный эффект, причём обнаруживается это обычно через несколько раундов. Приложение обязано делать
такую ошибку невозможной незаметно.

## Требования

<a id="fr-080"></a>
### FR-080 — Единственность концентрации

**Статус:** План · **Проверка:** unit `startConcentration replaces previous`, [AC-13](../quality.md#критерии-приёмки-mvp)

Одновременно может быть активно только одно концентрационное заклинание.

Это инвариант состояния, а не проверка интерфейса: структура данных допускает максимум одну запись
концентрации ([domain-model.md](../domain-model.md#состояние-персонажа)).

<a id="fr-081"></a>
### FR-081 — Предупреждение о замене

**Статус:** План · **Проверка:** E2E `second concentration warns`, [AC-13](../quality.md#критерии-приёмки-mvp)

При попытке запустить вторую концентрацию система должна показать: название текущего эффекта;
последствия завершения; кнопки «Отмена» и «Заменить концентрацию».

Это единственное предупреждение мастера применения, которое нельзя пройти кнопкой «Применить всё
равно»: требуется осознанный выбор одного из двух вариантов.

<a id="fr-082"></a>
### FR-082 — Постоянная видимость

**Статус:** План · **Проверка:** E2E `concentration visible on all screens`, [AC-14](../quality.md#критерии-приёмки-mvp)

Активная концентрация должна быть постоянно видна на главном экране.

<a id="fr-083"></a>
### FR-083 — Проверка концентрации при получении урона

**Статус:** План · **Проверка:** unit `concentrationCheckDc`, интеграционный по UC-04, [AC-15](../quality.md#критерии-приёмки-mvp)

Система должна поддерживать ручную проверку концентрации после получения урона.

КС рассчитывается как максимум из 10 и половины полученного урона (с округлением вниз).

Отображается спасбросок Телосложения, значение КС и модификатор персонажа. Бросок совершает
пользователь; приложение фиксирует результат — успех или провал.

## Поведение и крайние случаи

**Половина урона округляется вниз.** Урон 21 → КС 10 (половина равна 10), урон 22 → КС 11. Формула и
примеры — в [rules-engine.md](../rules-engine.md#кс-проверки-концентрации).

**Модификатор спасброска.** Берётся из состояния персонажа (`constitutionSaveModifier`), а не
вычисляется из характеристики: волшебник не владеет спасбросками Телосложения по умолчанию, но может
иметь черту, меняющую значение. См. [OQ-05](../open-questions.md#oq-05).

**Провал завершает эффект.** При провале снимается концентрация и закрывается связанный активный
эффект с причиной «провалена проверка концентрации». Это одна операция с одной записью журнала —
отмена возвращает оба состояния.

**Несколько источников урона.** Каждый экземпляр урона требует отдельной проверки. Приложение не
суммирует урон за раунд: суммирование дало бы неверную КС.

**Ручное снятие.** Пользователь может снять концентрацию вручную — заклинание закончилось по решению
игрока или мастера. Это не то же самое, что провал проверки: причина завершения фиксируется в журнале
разной.

**Незаметная потеря невозможна.** Любое завершение концентрации сопровождается видимым изменением
блока на главном экране; блок не может опустеть без записи в журнале.

## Проверка

| Что проверяем | Как |
|---|---|
| Невозможность двух одновременных концентраций | Unit на редьюсере состояния |
| Замена требует явного выбора | E2E: «Применить всё равно» не появляется |
| КС при урона 1, 19, 20, 21, 22, 40 | Unit, табличный тест |
| Провал закрывает и концентрацию, и эффект | Интеграционный |
| Отмена замены восстанавливает прежний эффект | Интеграционный через FR-111 |
| Блок концентрации виден после закрытия карточки | E2E, AC-14 |
