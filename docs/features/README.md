# Реестр фич

> Обновлено: 2026-07-31 · Статус: веха 1 в работе — логика применения реализована, интерфейса нет

Фича — единица планирования и поставки. Каждая имеет отдельный файл, где живут её требования,
поведение, крайние случаи и способ проверки. Требования нумеруются сквозной серией `FR-###` по всему
проекту, чтобы номер однозначно указывал на требование независимо от того, в какой фиче он лежит.

## Порядок реализации

Порядок определяется зависимостями, а не важностью. Фичи одного этапа можно делать параллельно.

```
Этап 1 — интерфейс на моках
  F-01 ─┬─ F-02 ─── F-03
        │
Этап 2 — движок правил (заменяет моки настоящим состоянием)
  F-06 ─┬─ F-07 ─── F-08
        ├─ F-05 ─── F-13
        ├─ F-09 ─── F-14
        ├─ F-15 ─── F-16
        └─ F-10

Этап 3 — контент
  F-04 (нужен профиль отыгрыша и заполненные карточки)

Этап 4 — платформа
  F-11 ─── F-12
```

`F-06` (ячейки и учёт хода) — фундамент второго этапа: от него зависят проверка доступности в `F-03`,
доступность реакции в `F-05` и восстановление ресурсов. Реализуется первой из движковых.

`F-10` (журнал) должен появиться одновременно с первой операцией, изменяющей состояние, иначе
требование обратимости `FR-111` придётся дописывать в уже написанный код.

## Что не является фичей MVP

Пункты из [product.md](../product.md#что-не-входит-в-mvp) не имеют файлов фич намеренно: у
нереализуемого не должно быть требований, иначе реестр перестаёт отражать реальный объём работ.
Идеи следующих версий живут в [constraints.md](../constraints.md#после-mvp).

## Требования

**Статус:** План · **Проверка:** способ проверки
Текст требования.

## Поведение и крайние случаи
## Зависимости
## Проверка
