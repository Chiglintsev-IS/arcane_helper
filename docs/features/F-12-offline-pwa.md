# F-12 — Офлайн-работа и установка на iPhone

> Статус: Готово · Этап: 4 · Обновлено: 2026-07-31
> Требования: NFR-001…NFR-003 · Источник: ТЗ §14.1, §15

## Зачем

Игра идёт за столом, где интернет может отсутствовать, а телефон — в авиарежиме. Приложение, которому
нужна сеть, в этот момент бесполезно. Офлайн — не оптимизация, а условие работоспособности.

## Требования

<a id="nfr-001"></a>
### NFR-001 — Полная работа без сети

**Статус:** Готово · **Проверка:** E2E `serves the app from cache when the network is gone`, [AC-02](../quality.md#критерии-приёмки-mvp)

После первой загрузки приложение должно полностью работать без интернета.

Стратегия — «сначала кэш»: за столом сеть либо отсутствует, либо хуже кэша, а всё содержимое
приложения статично. Список файлов сборки заранее неизвестен — статический экспорт даёт имена с
хешами, — поэтому при установке кэшируется только оболочка, а остальное оседает при первой загрузке.
Отсюда требование инструкции: приложение нужно один раз открыть до игры.

> **Как это проверено.** E2E ждёт, пока service worker возьмёт управление и наполнит кэш, глушит
> сеть перехватом и запрашивает страницу заново: ответ приходит из кэша. Перезагрузку под
> перехватом WebKit в тестовой сборке не выполняет, поэтому проверяется сам запрос — то же, что
> делает браузер при открытии в офлайне. Полная проверка в авиарежиме на телефоне остаётся ручной
> ([AC-02](../quality.md#критерии-приёмки-mvp)).

<a id="nfr-002"></a>
### NFR-002 — Доступное офлайн

**Статус:** Готово · **Проверка:** E2E `serves the app from cache when the network is gone`

Без интернета должны быть доступны: список заклинаний; карточки; мастер применения; отыгрыш; ячейки;
концентрация; активные эффекты; журнал; подготовка заклинаний.

То есть весь функционал MVP: разделения на онлайн- и офлайн-возможности нет. Это следствие
устройства, а не отдельная работа: сетевых запросов в рантайме нет вовсе
([ADR-0002](../decisions.md#adr-0002)), контент собран в сборку, состояние живёт в IndexedDB.

<a id="nfr-003"></a>
### NFR-003 — Обновление сохраняет данные

**Статус:** Готово · **Проверка:** unit `схема состояния`, E2E `state survives a reload`, [AC-18](../quality.md#критерии-приёмки-mvp)

Обновление приложения не должно удалять пользовательские данные.

Кэш статики версионируется и очищается при обновлении; база IndexedDB — нет: service worker её не
касается вовсе. Новые поля состояния добавляются со значением по умолчанию — так вошли `screenMode`,
`temporaryHitPoints` и роль в бою: сохранение, сделанное до их появления, продолжает читаться.

Обновление предлагается, а не применяется молча: новая версия ждёт в стороне, пока игрок не нажмёт
«Обновить». Незапрошенная перезагрузка посреди мастера применения потеряла бы черновик
([FR-022](F-03-cast-wizard.md#fr-022)).

## Поведение и крайние случаи

**Установка на домашний экран.** Манифест с `display: standalone`, иконки 192 и 512 пикселей,
`apple-touch-icon` на 180 и цвет темы ([AC-01](../quality.md#критерии-приёмки-mvp)). Пути в манифесте
относительные: статический экспорт кладут и в подкаталог, где абсолютный «/» сломался бы.

Иконки рисуются кодом (`scripts/make-icons.py`), а не хранятся картинкой из редактора: это та же
схема ритуала, что приложение рисует внутри ([ADR-0014](../decisions.md#adr-0014)), и повторить её
десятью строками дешевле, чем хранить растр, происхождение которого через полгода не восстановить.

Сама установка проверяется только руками: браузер не даёт странице узнать, добавлена ли она на
домашний экран.

**Ограничения Safari на iOS.** Данные IndexedDB могут быть удалены системой при нехватке места или
длительном неиспользовании установленного приложения. Отсюда следует обязательность экспорта
([F-11](F-11-data-io.md)) как способа резервного копирования и предупреждение в настройках. Обещать
пользователю вечное хранение нельзя — платформа такой гарантии не даёт.

**Обновление в офлайне.** Новая версия не может загрузиться без сети; приложение обязано продолжать
работать на прежней. Проверка обновлений никогда не блокирует запуск.

**Уведомление об обновлении.** Обновление не применяется молча посреди боя: показывается ненавязчивое
предложение перезагрузить. Незапрошенная перезагрузка во время мастера применения потеряет черновик.

**Отсутствующая сеть при первом запуске.** Первая загрузка требует сети — этого не избежать.
Пользователь должен один раз открыть приложение до игры, о чём говорит инструкция по установке.

## Как поставить на iPhone

Приложение — статические файлы: сборка кладётся на любой хостинг статики, телефон открывает адрес и
добавляет страницу на домашний экран.

**Обязательное условие — HTTPS.** Service worker регистрируется только в защищённом контексте;
исключение одно — `localhost`, а телефон по нему до ноутбука не достучится. Значит по локальной сети
через `http://192.168…` офлайна не будет: страница откроется, но в кэш ничего не ляжет и в авиарежиме
останется пустой экран. Это ограничение браузера, а не приложения.

1. Собрать: `npm run build`. Готовое лежит в `out/` — полтора мегабайта, включая все 29 карточек.
2. Дать телефону адрес по HTTPS. Настроены два пути, они не мешают друг другу:

   - **GitHub Pages** — постоянный адрес, собирается сам при каждом изменении `main`
     ([.github/workflows/pages.yml](../../.github/workflows/pages.yml)). `BASE_PATH` подставляет
     сам workflow: Pages отдаёт проект из подкаталога, и без него пути к файлам ведут в пустоту.
     Сайт открыт всему интернету — это цена постоянного адреса на обычных тарифах.
   - **Своя сеть Tailscale** — [scripts/serve-tailnet.sh](../../scripts/serve-tailnet.sh). Адрес
     стабильный и виден только своим устройствам, сертификат настоящий. Ноутбук нужен включённым
     только на время установки и обновления.

   Адрес менять нельзя: хранилище браузера привязано к нему, и с нового адреса приложение откроется
   пустым. Если переезд всё же нужен — состояние перевозится через «Данные»
   ([FR-120](F-11-data-io.md#fr-120)).
3. Открыть адрес в **Safari** — именно в нём, другие браузеры на iOS добавить на домашний экран не
   могут.
4. «Поделиться» → «На экран "Домой"» → «Добавить».
5. Запустить с домашнего экрана и **дать странице загрузиться до конца**. Одного открытия достаточно:
   service worker кладёт в кэш и оболочку, и файлы сборки при установке
   ([scripts/precache.py](../../scripts/precache.py)).
6. Включить авиарежим и запустить приложение с домашнего экрана ещё раз. Должны открыться экран боя,
   список заклинаний и карточка.

**Обновление.** Открытое с сетью приложение само замечает новую версию и предлагает кнопку
«Обновить» ([NFR-003](#nfr-003)); молча оно не перезагружается. Данные персонажа лежат в IndexedDB и
обновление их не касается.

## Проверка

| Что проверяем | Как |
|---|---|
| Полный сценарий UC-01 при выключенной сети | E2E `serves the app from cache when the network is gone` — частично: WebKit не выполняет перезагрузку под перехватом сети, поэтому проверяется ответ из кэша |
| Приложение открывается после одного посещения при погашенном сервере | Ручная проверка в Chrome 2026-08-01: сервер остановлен, перезагрузка отдала 29 карточек, `fetch` в сеть упал |
| Каждый пункт NFR-002 доступен офлайн | Чек-лист в игровой сессии в авиарежиме |
| Данные переживают обновление версии | Интеграционный: записать состояние → подменить версию → прочитать |
| Установка на домашний экран и запуск в standalone | Ручная проверка на реальном iPhone |
| Приложение стартует офлайн после перезапуска устройства | Ручная проверка |
