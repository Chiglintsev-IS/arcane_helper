## Где что заводится

**Новое поведение.** Найти домен, которому оно принадлежит, и добавить требование в его файл. Если
поведение задевает несколько доменов — оно принадлежит сценариям, а не одному из них.

**Новое понятие домена.** Сначала строка в глоссарии с именем в коде, потом
использование. Это защищает от расхождения «ячейка / слот / заряд» в одной кодовой базе.

**Техническая развилка.** Запись `ADR` в : контекст, варианты, выбор,
последствия. Решение, принятое молча в коде, считается непринятым.

**Неизвестное правило или число.** Запись `OQ-##` в открытых вопросах. Угадывать механику
запрещено.

## Правила этих документов

**Один факт — одно место.** Инвариант живёт в разделе «Инварианты» своего домена и больше нигде.
Число правил называется один раз, в домене, чей это ресурс. Глоссарий хранит имена, а не механику.

**Идея, а не реализация.** В доменных документах запрещены имена функций и файлов, сигнатуры, пути
`src/…` и номера строк: всё это живёт в коде, где обновляется само. Документ, переживающий
переименование функции, не приходится править из-за неё.

**История — в git.** Разделы вида «что показала примерка», «раньше было иначе», «решение
переписывалось» здесь не заводятся: они дублируют историю коммитов и устаревают молча.

## Формат требования

Требование определяется ровно один раз, в документе своего домена. Перед заголовком ставится явный
якорь `<a id="fr-070"></a>`: по нему на требование ссылаются, и он переживает правку заголовка.

```markdown
### FR-070 — Ячейки Торна

**Статус:** Готово · **Проверка:** unit `spellSlotsForLevel`

Текст требования в изъявительном наклонении: что система делает.
```

Идентификаторы не переиспользуются; отменённое требование получает статус `Отменено`, но номер
остаётся, чтобы ссылки из истории не ломались.

## Проверка целостности

```bash
npm run check:docs     # ссылки, якоря, требования, статусы
npm run check:layers   # границы слоёв и чистота комментариев
```

Первая ловит висячие ссылки и якоря, требования без определения, определённые дважды или не в своём
документе, потерянные требования ТЗ и статусы вне словаря. Вторая следит, чтобы код не приобретал
зависимостей, которых архитектура не допускает.
