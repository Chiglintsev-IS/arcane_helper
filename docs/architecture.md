# Техническая архитектура

> Обновлено: 2026-07-31 · Статус: согласовано · Источник: ТЗ §14–16, обоснование в [decisions.md](decisions.md)

## Формат приложения

Progressive Web Application. Обоснование выбора — [ADR-0001](decisions.md#adr-0001).

Следствия: установка на домашний экран без App Store, офлайн-работа, быстрые обновления, единая
кодовая база, возможность последующей упаковки в нативную оболочку.

## Стек

| Слой | Технология | Роль |
|---|---|---|
| Каркас | Next.js | Статическая сборка, маршрутизация, PWA-обвязка |
| Интерфейс | React + TypeScript | Компоненты |
| Стили | Tailwind CSS | Оформление, размеры зон нажатия, тема |
| Состояние | Zustand | Рантайм-состояние персонажа и черновика применения |
| Формы | React Hook Form | Подготовка заклинаний, настройки, ручные правки |
| Схемы | Zod | Валидация контента и импорта, вывод типов |
| Хранение | IndexedDB через Dexie.js | Персистентное состояние и контент |
| Офлайн | Web App Manifest + Service Worker | Установка и кэширование |
| Тесты | Vitest, React Testing Library, Playwright, axe-core | Unit, компонентные, E2E, доступность |

Обоснование ключевых выборов: [ADR-0002](decisions.md#adr-0002) (Next.js и статический экспорт),
[ADR-0003](decisions.md#adr-0003) (Zustand + Dexie), [ADR-0004](decisions.md#adr-0004) (Zod как
единственный источник схем).

## Принципы

Проект живёт долго и меняется от игры к игре: правила уточняет мастер, состав заклинаний — игрок.
Поэтому дешевизна изменения важнее краткости кода сегодня. Два правила, из которых всё остальное
выводится.

**Простота (KISS).** Абстракция вводится, когда у неё есть второй потребитель, а не в ожидании его.
Один способ сделать вещь вместо двух. Если выбор между «сложнее и точнее» и «проще и достаточно» —
проще, а разница записывается в спеку.

**Разделение ответственности (SOLID) там, где меняется чаще всего.** Пять принципов в этом проекте
означают конкретное:

| Принцип | Что означает здесь |
|---|---|
| Единственная ответственность | `rules/` считает, `store/` меняет состояние, `components/` показывает. Формула не знает о React, состояние не знает о базе |
| Открытость к расширению | новая операция над состоянием не требует правок в существующих: снимок отмены вычисляется сравнением, а не пишется руками ([ADR-0006](decisions.md#adr-0006)) |
| Подстановка | хранилище описано портом, у которого две взаимозаменяемые реализации, и обе проходят один и тот же набор тестов ([ADR-0009](decisions.md#adr-0009)) |
| Разделение интерфейсов | порт хранилища — три метода, а не «всё, что умеет база» |
| Инверсия зависимостей | состояние зависит от порта, а не от Dexie; браузерная база — деталь, заменяемая без правок логики |

**Практическая проверка.** Изменение правила должно требовать правки в одном месте: числа — в
`rules/`, поведение — в `store/`, текст — в контенте. Если правка расходится по трём файлам, дело в
структуре, а не в правке.

## Слои

```
┌─────────────────────────────────────────────┐
│ app/          экраны и маршруты             │  Next.js App Router
├─────────────────────────────────────────────┤
│ components/   презентационные компоненты    │  без доступа к хранилищу
├─────────────────────────────────────────────┤
│ store/        Zustand: состояние + действия │  единственная точка мутаций
├─────────────────────────────────────────────┤
│ rules/        движок правил                 │  чистые функции, без React
├─────────────────────────────────────────────┤
│ data/         схемы Zod, контент, миграции  │
├─────────────────────────────────────────────┤
│ хранилище     порт и две реализации         │  ADR-0009: Dexie и память
└─────────────────────────────────────────────┘
```

**Правило зависимостей: только вниз.** `rules/` не знает ни о React, ни о хранилище — это делает
формулы правил тестируемыми без окружения и гарантирует, что механика не зависит от интерфейса.
`components/` не обращается к хранилищу напрямую: состояние приходит из стора.

## Состояние и хранение

**Рантайм.** Zustand хранит `CharacterState`, журнал и черновик применения. Черновик — отдельный
стор: это техническая гарантия инварианта [FR-022](features/F-03-cast-wizard.md#fr-022), а не
договорённость.

**Мутации только через действия стора.** Каждое действие, изменяющее состояние, создаёт запись
журнала с `undoPatch` ([ADR-0006](decisions.md#adr-0006)). Прямая правка состояния из компонентов
запрещена — иначе требование обратимости [FR-111](features/F-10-journal-undo.md#fr-111) невозможно
удержать.

**Персистентность.** Каждое изменение состояния пишется в IndexedDB немедленно. Дебаунс отвергнут: он
сложнее и при этом теряет последнее действие, если приложение закрыли или система выгрузила вкладку.
Состояние Торна — единицы килобайт, для IndexedDB это ничто, так что экономить нечего.

Хранилище скрыто портом из трёх методов ([ADR-0009](decisions.md#adr-0009)): состояние зависит от
интерфейса, а не от Dexie. У порта две реализации — браузерная и в памяти, — и обе проходят один
набор тестов, поэтому логику можно проверять без браузера.

**Контент.** Заклинания хранятся в JSON в репозитории, проходят валидацию Zod при сборке и загружаются
в IndexedDB при первом запуске. Пользовательские дополнения (заметки, свои варианты отыгрыша) живут в
`CharacterState` и не перезаписываются обновлением контента.

**Миграции.** Схема БД версионируется средствами Dexie. Миграция обязана сохранять пользовательские
данные ([NFR-003](features/F-12-offline-pwa.md#nfr-003)); удаление таблицы с состоянием при обновлении
недопустимо.

## PWA и офлайн

**Манифест.** `display: standalone`, иконки под iOS, цвет темы, `orientation: portrait`.

**Service Worker.** Стратегии:

| Ресурс | Стратегия | Почему |
|---|---|---|
| Оболочка приложения (HTML, JS, CSS) | precache, cache-first | Мгновенный старт офлайн |
| Шрифты и иконки | cache-first | Не меняются |
| Контент заклинаний | precache | Обязателен офлайн ([NFR-002](features/F-12-offline-pwa.md#nfr-002)) |
| Внешние запросы | отсутствуют | Приложение не обращается к сети в рантайме |

Сетевых запросов в рантайме нет вовсе — это самая надёжная стратегия офлайна и заодно гарантия
приватности: данные не могут утечь, поскольку их некуда отправлять.

**Обновление.** Новый service worker не активируется молча: пользователю показывается предложение
перезагрузить. Перезагрузка посреди мастера применения потеряла бы черновик.

## Тестирование

Стратегия и матрица трассировки — в [quality.md](quality.md). Технически:

- Vitest — движок правил и сторы; движок покрывается полностью, поскольку это место, где ошибка
  означает неверную игру;
- React Testing Library — компоненты с логикой (фильтры, шаги мастера);
- Playwright — сценарии [UC-01…UC-05](use-cases.md) в мобильных viewport, включая офлайн-режим;
- axe-core — базовая доступность экранов.

## Ограничения платформы

**Safari на iOS.** IndexedDB может быть очищена системой при нехватке места. Отсюда обязательность
экспорта ([F-11](features/F-11-data-io.md)) и предупреждение в настройках.

**Буфер обмена.** Запись в буфер требует пользовательского жеста: копирование выполняется
синхронно по нажатию.

**Отсутствие фоновой работы.** Таймеры и уведомления в установленном PWA на iOS ненадёжны — ещё одна
причина не отсчитывать длительность эффектов автоматически в MVP
([F-08](features/F-08-active-effects.md)).

## Роль ИИ

ИИ не используется в критической механике MVP. Правила, числовые значения и проверки хранятся
структурированно.

В будущих версиях ИИ допускается только для художественного слоя: генерация реплики, описания жеста,
смена тона, адаптация текста под ситуацию. ИИ запрещено изменять уровень заклинания, урон, дальность,
спасбросок, концентрацию, компоненты, длительность и стоимость применения. Любой сгенерированный текст
строится поверх проверенной механической карточки. Формально — [ADR-0005](decisions.md#adr-0005).
