# Архитектура

Arcane Helper — PWA для одного игрока и одного персонажа: статический экспорт без сервера, ставится
на домашний экран iPhone из Safari и целиком работает без сети — состояние живёт на устройстве.
Логика отделена от отображения договором сообщений, поэтому та же логика без правок поднимается и в
серверном процессе: это вторая, сетевая поставка.

## Поставка

**Статический экспорт** — основная поставка. Сервера нет; в рантайме приложение обращается только к
собственной статике. Публикуется на GitHub Pages в подкаталоге с именем репозитория: базовый путь
приходит из окружения сборки, ссылки на манифест и иконки относительные. Для установки на телефон
сборку раздают по HTTPS внутри своей сети: без настоящего сертификата service worker не
регистрируется, а без него офлайна нет.

**Сетевая поставка** выбирается одной переменной сборки, которая решает сразу два вопроса: провод до
логики идёт по сети, а сборка перестаёт быть статическим экспортом, потому что тот не исполняет
обработчиков маршрутов. Маршруты бэкенда носят собственное расширение файла и существуют только в
этой сборке; их четыре — открыть сессию, прочитать сырое сохранение, исполнить команду, задать
вопрос — и каждый лишь передаёт тело двери ядра. Ядро одно на процесс, хранилище оперативное:
перезапуск начинает партию заново; адрес и есть доступ, поставка личная и живёт время партии. Логика
в браузер не едет: композиционный корень отображения берёт ядро отложенным импортом, и страница,
выбравшая сеть, не загружает ни одного модуля логики. Офлайн эта поставка не обещает.

**PWA.** Одна страница; манифест объявляет отдельное окно, портретную ориентацию, русский язык и
иконки; из поисковой индексации приложение исключено. **Service worker** отвечает «сначала кэш» на
GET-запросы к собственной статике; чужие домены и обращения к бэкенду идут мимо кэша. При установке
в кэш кладутся оболочка и файлы сборки: их имена содержат хеш, поэтому список вписывает в воркер шаг
сборки после экспорта — без него скрипты оседали бы в кэше со второй загрузки, и игрок, открывший
приложение дома один раз, получил бы за столом пустой экран. Новая версия не активируется молча:
страница предлагает «Обновить» или «Позже», активирует воркер сообщением и перезагружается; прежние
кэши удаляются при активации. Данные игрока живут в IndexedDB и в кэш не попадают.

## Стек

| Слой | Технология |
|---|---|
| Каркас и сборка | Next.js (App Router, статический экспорт; типы проверяет CLI компилятора TypeScript) |
| Интерфейс | React + TypeScript |
| Стили | Tailwind CSS; цвета — токены ролей, тема светлая и тёмная по системной настройке |
| Состояние отображения | Zustand |
| Схемы и типы | Zod: типы выводятся из схем, одна схема проверяет контент, импорт и сохранение |
| Хранение | IndexedDB через Dexie |
| Офлайн | Web App Manifest + service worker |
| Прогоны | Vitest и React Testing Library; Playwright на WebKit, axe-core; стражи — Python в `scripts/` |
| CI и публикация | GitHub Actions: проверка на каждой ветке, публикация только с `main` |

## Корни и слои

```
src/contract/         договор сторон: команда, снимок, ответ, вопрос, сырое сохранение, порт, провод
src/core/             логика
  domain/             ограниченные контексты; shared — основа; assembly — сборка корня персонажа
  application/        сценарии (сгруппированы предметно) и порты хранилища и часов; про договор не знает
  presentation/       входящие адаптеры: разбор сообщения, перевод команды в сценарий, проекции снимка
  infrastructure/     исходящие адаптеры: Dexie, память, системные часы, встроенный каталог
src/shared/           язык: морфология и слова правил, которые произносят обе стороны
src/ui/               отображение по FSD: app → screens → widgets → features → entities → shared
src/app/              маршруты Next: страница монтирует интерфейс, дверь бэкенда зовёт ядро
```

**Контексты домена:** персонаж, магические ресурсы, каталог, книга заклинаний, эффекты, здоровье,
снаряжение, вещи, ремесло, схватка, лог, заметки, лист. Основу читают все; сборку не знает никто.
Рёбра между контекстами названы явным списком: каталог читают книга, ресурсы, эффекты и ремесло;
лист складывает персонажа, снаряжение, вещи, эффекты и каталог; снаряжение знает вещи; схватка
читает лог. Корень агрегата — персонаж: он собирает объекты-значения контекстов и их вклады; лист —
производная от базы, надетого и действующего, одним кодом для итога и предпросмотра. Сборку ядра
знает один модуль, видящий все четыре слоя; сборок две: браузерная на Dexie и серверная на памяти.

**Договор.** Команда — намерение данными: вид и параметры идентификаторами, не объектами; едет в
конверте с идентификатором попытки. Снимок — единственное чтение: версия, посчитанные проекции всех
экранов, лог, заметки, закрытые списки правил и пределы для полей ввода, источник каталога. Ответ —
применено со снимком либо отказано с причиной по-русски. Вопрос — про то, чего в состоянии нет
(набираемые числа); ответ — предпросмотр без версии, состояния не меняет и в лог не пишется. Сырое
сохранение — содержимое хранилища текстом с именем файла, когда разбор отказал. Порт — четыре
операции: открыть, прочитать сырое, исполнить, спросить. Реализация порта одна — клиент, разбирающий
схемами договора всё в обе стороны; подменяется только провод: в процессе — через сериализацию в
JSON, чтобы игра без сети доказывала сетевой договор, — либо по сети. Схема договора проверяет
форму, а не правила; слов предметной области в ней нет — строку сужает владелец списка. Нарушение
договора — дефект сборки, не отказ правила, и игроку словами правил не объясняется.

**Отображение.** Оболочка держит панель режимов, провайдеры и выбор экрана; каждый режим — свой
экран (игра, книга, лист, вещи, ремесло, отдых, лог, заметки) со своими шторками. Сторов два: сессия
— зеркало ядра со снимком, статусом, причиной отказа и сырой копией; черновик применения — выбор
игрока в мастере, ничего не считает по правилам и состояния не касается.

## Границы

Правила зависимостей проверяются скриптами, а не памятью.

- Логика не знает про отображение и маршруты; прогон ядра — тоже. Домен импортирует только домен и
  язык. Прикладной слой не тянет реализацию мимо порта.
- Рёбра между контекстами — только из явного списка; циклов между контекстами и между модулями
  одного контекста нет. Долг рёбер записан базлайном, и он пуст.
- Отображение видит из логики только договор. Исключения названы поимённо: композиционный корень,
  прогонная сборка сторов, язык. Отложенный импорт считается импортом.
- Внутри `src/ui/` импорт идёт только вниз по слоям; слайсы одного слоя друг о друге не знают;
  каталог из одних прогонов слайсом не считается; суффикс «экран» носит только экран.
- Реэкспортов и барелей нет: наружу модуля ведёт явный путь до владельца символа. Экспорт ядра без
  импортёра в рабочем коде не живёт. Код не ссылается на документацию ни путём, ни номером.
- Мутация — через корень агрегата: отображение не коммитит и не правит агрегат; сценарий не
  дописывает полей мимо владельца; полная схема состояния — только спреды владельцев; агрегат
  объявляет, чем владеет.
- Одна фраза — один владелец: русский литерал длиннее 15 знаков не встречается в двух рабочих
  файлах. Отображение не считает по правилам игры, не проверяет доменных инвариантов, не обрезает
  дробный ввод; сокращения монет, размер кости, слова кнопок, линейки и ступени подложки приходят
  от владельца. Состояние для прогона собирается операциями контекстов, а не словарём чисел.
- Типы не подделываются: приведение вне `as const`, `any` и директивы, глушащие компилятор, —
  ошибка; исключение живёт у операции-владельца с обоснованием.
- Прогон лежит рядом со своим предметом, импортирует его и не даёт ему псевдонима.

## Состояние и хранение

**Состояние персонажа** — одна схема, собранная спредом из подсхем контекстов; своих полей у сборки
нет, инварианты контекста — его доводчики. Состояние глубоко неизменяемо: правка — новое состояние
через объект-значение контекста и корень. Производное не хранится: лист, доступность действий и
отметка боя считаются из состояния и лога.

**Владеет состоянием ядро.** Сессия — персонаж и лог; живая сессия добавляет каталог карточек и его
источник (сборка или загруженный игроком). Отображение состояния не хранит: снимок — единственное
чтение. Повтор попытки узнаётся по идентификатору в логе и отвечает текущим снимком без изменений;
отказ владельца правила становится ответом; целостность ссылок книги на каталог проверяется до
записи; запись в хранилище идёт до ответа. Версия снимка растёт с каждой применённой командой; ответ
с версией меньше показанной не показывается, чтение же приносит новую правду целиком.

**Лог** дополняется с конца, глубина — 100 записей. Запись несёт снимок изменённых полей до правки по
списку обратимых полей — все, кроме справочных полей листа; отменяется последняя запись, собранное
состояние проверяется схемой целиком. Запись без снимка остаётся историей и отмене отказывает.
Ресурсы хода и отметка боя выводятся из записей после последнего начала хода, а не хранятся флагами.
Правки, ничего не расходующие, — заметка к заклинанию, запись о мире — лога не заводят.

**Хранилище** скрыто портом из четырёх операций: прочитать, прочитать сырое, записать, очистить.
Реализации две — IndexedDB через Dexie (одна таблица, одна запись) и память (прогоны и сервер), —
и обе проходят один набор проверок. Сессия пишется целиком на каждое изменение. Формат записи имеет
свою версию (сейчас 3): запись новее — отказ «обновите приложение»; прежние формы приводятся при
чтении, включая снимки отмены, из которых снимаются поля, неизвестные состоянию; схема самой базы
Dexie неизменна. Испорченная запись не затирается и не загружается: экран показывает причину,
отдаёт сырую копию файлом или в буфер и предлагает начать заново — иначе хранилище на телефоне не
очистить.

**Каталог и обмен.** Встроенные карточки в запись не попадают: копия заморозила бы книгу на дате
установки. Хранится только каталог, загруженный игроком; отсутствие поля означает встроенный, и книга
при чтении сужается до карточек сборки. Выгрузка — файл своей версии (сейчас 7) с персонажем целиком
и карточками; имя файла несёт дату от часов ядра. Импорт разбирается той же схемой, что читает
собственный контент: файл прежней версии приводится, неизвестной — отклоняется, провал не трогает
данных; принятый импорт заменяет персонажа и каталог и начинает лог заново.

**Состояние интерфейса** — режим экрана, раскрытая часть «Вещей» — живёт в localStorage браузера и
в сохранение не попадает.

## Тексты и ИИ

Карточка заклинания делит механические поля — уровень, школа, время, компоненты, урон и его
масштабирование, спасбросок — и тексты: пересказ правил своими словами и тактический совет. Расчёт
читает только механические поля; тексты на него не влияют и изменить его не могут. Числа берутся из
подтверждённых источников; ИИ допустим только для текстов. Каждая карточка проходит схему при
загрузке — ту же, что принимает импорт игрока, — а прогон каталога сверяет тексты с правилами записи:
совет не называет других заклинаний книги и содержит числа, масштабирование не ниже уровня.

## Проверка

`npm run verify` — один вход, по шагам: изоляция и абстрактность документов → границы слоёв и контекстов →
живость экспортов ядра → владение фразами и правилами → честность типов → проверка типов
компилятором → прогоны с покрытием → сборка. `npm run verify:full` добавляет E2E обеих поставок.

**Прогоны.** Порог покрытия — 100 % строк, функций, ветвей и операторов по `src/core/**`,
`src/shared/**`, `src/ui/**/model/**` и `src/ui/**/lib/**`: ошибка там не выглядит сбоем, а
проявляется неверно проведённой игрой; разметка проверяется поведением, не порогом. Прогон лежит
рядом со своим предметом: имя файла до первой точки — предмет, дальше аспект, затем `.test`. Среда
по умолчанию node; компонентный прогон просит jsdom директивой и поднимает настоящее ядро на
хранилище в памяти через локальный провод — моков нет; обстановка набирается командами, часы
детерминированы.

**E2E.** Playwright на WebKit — движке Safari — в viewport iPhone SE: на нём проверяется «ключевая
механика без прокрутки». Статическая поставка раздаётся из каталога экспорта; сетевая — сервером
фреймворка с той же переменной сборки, прогоны по очереди, потому что сессия у бэкенда одна; партия
через него доказывает, что в браузере не остаётся ни одной базы. Доступность — axe-core по всем
режимам и шторкам в обеих темах. Офлайн проверяется ответом из кэша при заглушённой сети; установку
с домашнего экрана и авиарежим проверяет игрок на телефоне.

**CI.** На каждый push и pull request — `verify` и E2E статической поставки на WebKit. Публикация
идёт отдельным процессом только с `main`: `verify`, сборка с базовым путём Pages, выгрузка; одна
публикация за раз, начатая не обрывается.

## Ограничения платформы

- **Хранилище могут очистить.** Safari на iOS вправе удалить IndexedDB при нехватке места или долгом
  неиспользовании: отсюда выгрузка как резервная копия и сырая копия при непрочитанном сохранении.
- **Файлы и буфер.** Работа с файлами в Safari ограничена, поэтому рядом со скачиванием стоит
  копирование в буфер обмена; запись в буфер идёт по нажатию — жест пользователя обязателен.
- **Приватный режим** бросает на обращении к localStorage: чтение обёрнуто, пусто значит «не выбрано».
  Читается оно после гидратации: статическая разметка приходит без хранилища.
- **Полноэкранный режим** до iOS 17 читается из устаревшего мета-тега — он стоит рядом с
  современным. Верхний системный отступ держит оболочка, панель режимов стоит у нижнего края.
- **Фоновой работы нет:** таймеры и уведомления в установленном PWA ненадёжны, поэтому длительности
  эффектов по часам не отсчитываются — срок отмеряют начала ходов, окончание заклинания или игрок.
- **Обновление** без спроса потеряло бы черновик мастера — новая версия ждёт согласия. Зоны нажатия
  не меньше 44 × 44 px, масштабирование не запрещено.
