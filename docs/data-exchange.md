# Обмен данными и офлайн

Данные живут в браузере, который вправе их очистить: выгрузка — резервная копия и переезд.

## Выгрузка

В файл попадает всё, чем играют: персонаж с остатком ресурсов, карточки каталога, книга и
подготовленный набор, профиль отыгрыша с заметками и отметками. Формат — JSON с номером версии
схемы: без неё прежние копии станут нечитаемыми.

Вход к выгрузке и загрузке — режим «Журнал» ([FR-222](screens.md#fr-222)).

## Загрузка

Проверяются по очереди версия, структура с типами и диапазонами и ссылочная целостность: наборы
персонажа ссылаются на существующие карточки (Каталог заклинаний). Файл более
новой версии отклоняется целиком. Отказ называет проблемное поле и суть ошибки.

Импорт атомарен: персонаж и каталог заменяются одной записью, при отказе прежнее состояние
нетронуто — половины импорта не существует. Журнал при замене персонажа начинается заново
(Журнал).

## Хранение

Сессия — персонаж, журнал и каталог — читается и пишется целиком, иначе поля разойдутся. Каждое
изменение пишется немедленно. Повреждённое сохранение не затирается, а объявляется
повреждённым; сохранение более новой версии формата не читается. Обновление приложения хранилища не
касается, новые поля состояния появляются со значением по умолчанию.

## Офлайн

Сетевых запросов в рантайме нет вовсе: контент лежит в сборке, состояние — в браузере, отправлять
данные некуда. Статика отдаётся из кэша, поэтому приложение открывают один раз до игры и по HTTPS.
Приложение ставится на домашний экран отдельным окном. Обновление предлагается кнопкой, а не
применяется молча: перезагрузка посреди мастера применения потеряла бы черновик. Хранилище на iOS
может быть очищено системой, поэтому выгрузка обязательна.

## Требования

<a id="fr-120"></a>
### FR-120 — Состав выгрузки

**Статус:** Готово · **Проверка:** unit `exportSnapshot (FR-120)`, [AC-19](quality.md#критерии-приёмки-mvp)

Выгружается лист персонажа целиком — вид, возраст, размер, скорость, подкласс, характеристики,
владения, прибавки предметов, перебивки, истощение и вдохновение, — а с ним заклинания,
подготовленный набор, профиль отыгрыша, текущее состояние ресурсов, заметки и отметки игрока.
Формат — JSON с версией схемы.

<a id="fr-121"></a>
### FR-121 — Проверка импорта

**Статус:** Готово · **Проверка:** unit `parseImport (FR-121)` на корректных и битых файлах

Импорт проверяется по схеме: структура, типы, диапазоны (уровень 0–9, характеристика 1–30, ступень
истощения 0–6, остаток не больше максимума) и ссылочная целостность против каталога. Отказ называет
поле и суть ошибки.

<a id="fr-233"></a>
### FR-233 — Приведение данных прежней версии

**Статус:** Готово · **Проверка:** unit `сохранение каждой версии открывается целиком, и числа за
столом не едут`, unit `ни одно число не едет: прежние производные становятся перебивками`, unit
`признак магического восстановления становится дневным бюджетом`, unit `род вещи становится
категорией`, unit `прибавка и база доспеха вне экипировки снимаются, а сохранение читается (FR-238)`, unit `«прибавки без вещи» становятся прочими прибавками персонажа`, unit `поправка к КД
получает типизированный признак`, unit `поля, которые перестали принадлежать персонажу, читаются и
отбрасываются`

Сохранение и выгрузка любой прежней версии читаются с приведением, и ни одно число за столом не
меняется. Файл версии новее той, что понимает приложение, по-прежнему отклоняется целиком: «понял
частично» здесь значит «молча потерял».

Что приводится, считая от самой ранней версии:

- Характеристики восстанавливаются там, где выводимы из прежних производных чисел, а сами
  производные становятся перебивками листа — видно, что они введены руками, и за столом действуют
  ровно те, что были.
- Один максимум хитов распадается на базу и снижение кровью; мастерского снижения прежде не было.
- Признак «восстановление доступно» становится дневным бюджетом уровней ячеек: оба его состояния —
  ровно полный бюджет или ровно нулевой остаток.
- Плоское снаряжение с одними компонентами становится сумкой; сведения о компонентах сохраняются.
- Рода вещей становятся категориями сумки: зелье расходником, хлам «другим», вещь без рода — по
  поведению. Надетость, прибавки и база доспеха вне экипировки снимаются, счёт выше предела
  обрезается пределом.
- Хранимая база Класса Доспеха становится перебивкой листа, если отличается от базы без доспехов:
  имя доспеха приведение не выдумывает. Прибавки, не названные вещью, становятся прочими прибавками
  самого персонажа, а не снаряжения.
- Поправка к Классу Доспеха среди активных эффектов получает признак вместо опознания по имени.
- Поля, которые перестали принадлежать персонажу, читаются и отбрасываются: режим экрана — состояние
  интерфейса ([FR-204](screens.md#fr-204)), а учёт израсходованного в ходу и доступность реакции
  считаются по журналу ([FR-144](domains/encounter.md#fr-144)). Сохранение с ними открывается, в состоянии
  их не остаётся.

Приведению подлежат и снимки отмены журнала: без этого отмена старой записи вернула бы в состояние
формы данных, которых нынешняя модель не знает.

<a id="fr-122"></a>
### FR-122 — Атомарность импорта

**Статус:** Готово · **Проверка:** компонентный `битый файл называет причину и состояние не трогает`

При ошибке импорта существующие данные не изменяются: файл берётся целиком либо не берётся.

<a id="nfr-001"></a>
### NFR-001 — Полная работа без сети

**Статус:** Готово · **Проверка:** E2E `serves the app from cache when the network is gone`, [AC-02](quality.md#критерии-приёмки-mvp)

После первой загрузки приложение полностью работает без интернета.

<a id="nfr-002"></a>
### NFR-002 — Доступное офлайн

**Статус:** Готово · **Проверка:** E2E `serves the app from cache when the network is gone`

Без интернета доступен весь функционал MVP: список заклинаний, карточки, мастер применения, отыгрыш,
ячейки, концентрация, активные эффекты, журнал, подготовка заклинаний.

<a id="nfr-003"></a>
### NFR-003 — Обновление сохраняет данные

**Статус:** Готово · **Проверка:** unit `форма состояния`, unit `отсутствующие поля получают
значение по умолчанию: обновление не теряет данных`, E2E `state survives a reload`,
[AC-18](quality.md#критерии-приёмки-mvp)

Обновление не удаляет пользовательские данные: очищается только версионированный кэш статики. Новая
версия ждёт подтверждения игрока.
