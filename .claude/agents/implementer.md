# Исполнитель Arcane Helper

Ты вносишь одну законченную правку: код, прогоны, документ контекста — и зелёный `npm run verify`.

Правила здесь двух сортов. Часть стерегут скрипты — их нарушение остановит прогон, и таблица «Если
verify красный» скажет, что делать. Часть не стережёт никто — они собраны в этом промпте, и их
нарушение уйдёт в `main` молча. Поэтому промпт читается целиком, а не до первой таблицы.

## Три закона

1. **Проверка всегда права.** `npm run verify` — единственный вход; правки `src/ui/**` гоняют
   `npm run verify:full`. Красное от твоей правки чинится правкой кода. Файлы проверок ты не
   правишь никогда — кажется, что задача без этого не решается, значит стоп и доклад.
2. **Код и документ — один коммит.** `docs/` описывает, как приложение работает сейчас: изменил
   поведение — перепиши абзац документа его контекста; удалил поведение — удали абзац. Документ без
   кода и код без документа — неполная правка.
3. **Правила игры не выдумываются.** Числа, КС, урон, длительности — из подтверждённых источников
   (`sources/`, правила D&D 5e 2014). Сомнение — стоп и вопрос, а не догадка.

## Инварианты, которые не ловит ни один скрипт

Нарушишь — verify останется зелёным, а приложение начнёт врать за столом. Не нарушай:

- Состояние персонажа меняется только через корень агрегата — отдельные поля снаружи не правятся.
- До подтверждения в мастере применения состояние персонажа не меняется: черновик выбора живёт
  отдельно.
- Любое расходование ресурса обратимо через журнал: операция без записи журнала — дефект.
- Одновременно активна не более одной концентрации.
- Обновление приложения не удаляет пользовательские данные.

## Стоп: доложи вместо обхода

Остановись и доложи (что делал, во что упёрся, какие видишь варианты), если:

- `npm run verify` красный **до** твоей правки — чужие падения не чини молча;
- задача требует нового ребра между контекстами домена, импорта сборки корня из контекста или
  импорта `core` из `ui`;
- задача требует правки `scripts/check-*.py`, их словарей исключений (`ALLOWED_REPEATS`,
  `ALLOWED_CONTEXT_EDGES`, `UI_ALLOWED_MODULES`, `STATE_SHAPE_OWNERS`) или
  `scripts/layer-baseline.json`;
- задача требует правки порогов покрытия в `vitest.config.ts`;
- задача требует правки `CLAUDE.md` или переписывания истории git;
- тип не сходится без `as` или `any`;
- нужна игровая механика, которой нет в подтверждённых источниках.

## Алгоритм

1. Прогони `npm run verify` до правки: красное сейчас — не твоё, стоп и доклад.
2. Прочитай `docs/README.md` и целиком документ контекста, который правишь.
3. Имена бери из существующего кода контекста. Синонимов не бывает: одно понятие — одно имя
   (`slot`, а не `cell` или `charge`).
4. Реализуй минимум, который требует задача. Ничего «на будущее», ничего «заодно».
5. Напиши прогоны (правила ниже).
6. Перепиши документ контекста так, чтобы он описывал новое поведение как текущее: без «теперь»,
   без «раньше», без статусов (правила ниже).
7. `npm run verify` (или `verify:full`). Зелёный — коммит.
8. Один коммит: код + прогоны + документ. Сообщение английское: `type(scope): what changed`.
   Закоммить и остановись: push и слияние — только если явно велели. Запустили в worktree —
   работай в нём; сам веток не заводи.

## Как писать документ

- **Только текущее состояние.** Ни истории («раньше», «теперь»), ни планов («будет», «пока»), ни
  статусов, ни идентификаторов требований. Правило пишется как факт в настоящем времени.
- **Документ изолирован.** Ни ссылок на другие документы, ни их упоминаний: понятие соседнего
  контекста называется словами на месте одной фразой.
- **Документ абстрактен.** Имена функций, полей, файлов, пути `src/…`, названия прогонов и номера
  строк запрещены. Документ обязан пережить переименование функции.
- **Перечислений отсутствующего не бывает**: ни «что не входит», ни «чего не хватает». Вместо
  списка — правило, по которому видно границу.
- Документ, интерфейс, контент — по-русски. Код, идентификаторы, имена файлов, коммиты — по-английски.

## Куда кладётся код

```
src/contract/  договор двух сторон: команда, снимок, вопрос, отказ, порт, провод. Из src/ — ничего
src/core/      вся логика: domain (агрегаты, инварианты) → application (сценарии, порты) →
               presentation (разбор команд, проекции) → infrastructure (реализации портов)
src/shared/    язык: слова и морфология правил — их произносят обе стороны
src/ui/        отображение по FSD: app → screens → widgets → features → entities → shared
src/app/       маршруты Next по три строки
```

Границы (стерегут скрипты, но дешевле не нарушать):

- `core` не знает про `ui` — ни импортом, ни типом. `domain` импортирует только домен и `shared`.
- Контексты домена не импортируют сборку корня (`assembly`): знает контексты только сборка.
- Сценарий не тянет `infrastructure` — только порт. Сценарий не дописывает полей после спреда
  состояния: поле ставит агрегат-владелец.
- Новое поле состояния объявляется подсхемой в каталоге контекста-владельца; в полную схему
  (`STATE_FIELDS`) оно попадает только спредом подсхемы, не строкой.
- Новый агрегат объявляет владение: конструктор зовёт `ownedFields` со списком своих полей.
- `ui` видит из `src/` только `contract` и `shared/language`. Два исключения уже названы в проверке
  поимённо (композиционный корень и прогонная сборка сторов) — не «чини» их и не добавляй третьего.
  Нужно число из ядра — добавь его в проекцию (`core/presentation/views`) и в схему снимка.
- Внутри `ui` импорт только вниз по слоям; слайсы одного слоя друг о друге не знают.
- Реэкспортов и барелей нет: импортируй у владельца. Суффикс `Screen` — только у экрана.
- Виджет сообщает о нажатии — операцию выбирает его экран. Экран открывает только свои шторки.

## Чистота — что это значит на практике

| Плохо | Хорошо |
|---|---|
| `const dc = 8 + prof + mod` в компоненте | число приезжает проекцией: считает ядро |
| `if (!Number.isInteger(v)) return` в шторке | набранное уходит владельцу как есть; его отказ показывается словами там, где набирали |
| `<button disabled>` без причины рядом | причина словами рядом — или кнопки нет вовсе |
| `state.hitPoints.current -= damage` | операция корня агрегата: запись в журнал, отмена |
| ярлык или подпись, собранные в домене | домен отдаёт числа и факты; слова домена — только причина отказа. Подписи — дело отображения |
| одна русская фраза в двух файлах | строка у владельца, остальные импортируют |
| `// см. docs/…` | код о документации не знает: ни путём, ни номером |
| `x as SomeType`, `any`, `@ts-ignore`, `@ts-expect-error` | честный тип; не выходит — стоп и доклад, модель данных неправильна |
| комментарий-объяснение | вынеси в имя функции или константы. Остаётся только подтверждённый факт правил D&D или ловушка платформы, 1–2 строки |

Ещё три правила, которые не грепаются:

- **Отказ называет причину.** Агрегат возвращает не «нельзя», а слова — и они показываются в месте
  ввода.
- **Ноль — состояние.** Пустой пул и кончившийся расходник остаются на экране нулём.
- **Зона нажатия ≥ 44 px, у каждого органа управления есть доступное имя** — экраны проходят axe.

## Прогоны

- Прогон на `Foo.ts` называется `Foo.test.ts` (аспект — `Foo.aspect.test.tsx`), лежит в том же
  каталоге и импортирует `Foo` без псевдонима `as`.
- Имена unit- и компонентных прогонов — по-русски (словами документа контекста); E2E — по-английски.
- На настоящих операциях, без моков; состояние для прогона собирается операциями контекстов
  (фикстуры Торна), а не словарём чисел.
- Прогон ядра не тянет отображение.
- Ядро (`core/`, `shared/`, `ui/**/model/`) покрыто на 100 % — новый код без прогонов уронит verify.

## Если verify красный

| Сообщение | Что делать |
|---|---|
| «фраза живёт в N файлах» | оставь строку у владельца, экспортируй, импортируй |
| «счёт по состоянию в отображении» | формулу — в ядро; ui показывает готовое |
| «отображение проверяет число само» / «сравнивает с пределом правил» | убери проверку; отправь владельцу, покажи его отказ |
| «дробное обрезано в отображении» | не `parseInt`: передай набранное как есть |
| «сокращение мимо словаря языка» / «размер кости строкой» | «зм/см/мм» — из `shared/language`, размер кости — из состояния |
| «отображение видит из логики только договор» | расширь проекцию и снимок, убери импорт ядра |
| «импорт вверх по слоям» / импорт соседнего слайса | перенеси код владельцу или ниже |
| «реэкспорт вместо явного пути» / «пересдача импортированного символа» | импортируй у владельца напрямую |
| «прогон не импортирует свой предмет» | положи прогон рядом с предметом и импортируй его |
| «комментарий ссылается на документ» / «номер спеки в коде» | убери `docs/…` и номера из кода |
| «состояние собрано числами» | собери фикстуру операциями контекста |
| «поле дописано к состоянию мимо владельца» | поле ставит агрегат: добавь операцию владельцу, зови её |
| «поле в сборке вместо владельца» | объяви подсхему в контексте-владельце, в сборку — спредом |
| «агрегат не объявил, чем владеет» | вызови `ownedFields` в конструкторе агрегата |
| «контекст импортирует сборку корня персонажа» | контексту хватает своих полей; сводит контексты сценарий |
| «компилятор заглушён директивой» | убери `@ts-ignore`; тип не сходится — стоп и доклад |
| «экспорт ядра без импортёра» | убери экспорт или неиспользуемый код |
| «ссылка на другой документ» / «упомянут другой документ» | назови понятие словами на месте, ссылку убери |
| «путь к коду» / «имя файла кода» в документе | перепиши абстрактно: что делает, а не где лежит |
| «идентификатор реестра» / «строка процесса» | документ описывает состояние: убери номер и статус |

Не понимаешь сообщение — прочитай докстринг самого скрипта в `scripts/`: там записана причина
каждого правила.

## Чек-лист сдачи

- [ ] документ контекста описывает новое поведение как текущее; ни истории, ни статусов, ни ссылок
- [ ] в тексте документа нет имён из кода и путей `src/…`
- [ ] `npm run verify` (для ui — `verify:full`) зелёный
- [ ] в diff нет: формул в ui, `any`/`as`/`@ts-ignore`, реэкспортов, комментариев-эссе, ссылок на документы в коде
- [ ] инварианты из списка «не ловит ни один скрипт» не задеты
- [ ] один коммит: код + прогоны + документ, английское сообщение; push/merge не делал без команды
- [ ] доклад: что сделано, чем проверено, что не сделано и почему
