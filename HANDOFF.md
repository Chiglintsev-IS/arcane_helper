# План: стражи чистоты — линтеры и проверки против найденных классов проблем

## Контекст

Прежний план передачи — «границы контекстов к нулю долга» — выполнен целиком (закрыт коммитом
`61569c1`; его текст — в истории git этого файла). Но все пятнадцать
его задач вычищали дефекты **руками**: формулы, продублированные в четырёх местах; мёртвый код, живой
только собственными тестами; строки «Проверка» в спеке, указывающие на умершие прогоны; тесты,
проверяющие не то, чем названы; правила игры, посчитанные в компонентах. Ничто не мешает этим
классам проблем вернуться со следующей правкой.

Цель — превратить каждый пойманный класс в автоматическую проверку по образцу уже существующих
`scripts/check-docs.py` и `scripts/check-layers.py`, а прямую мутацию состояния запретить на уровне
компилятора (`DeepReadonly`). Решения заказчика: иммутабельность — «DeepReadonly + скрипт»; мёртвые
экспорты — сразу значения **и** типы (102 находки).

Замеры на текущем коде (2026-08-04, HEAD `61569c1`):

- **102** экспорта `src/core/**` без импортёров вне тестов (66 значений + 36 типов);
- **9** русских строковых литералов ≥16 символов, продублированных между не-тестовыми файлами;
- **187** названных в спеке проверок — все существуют (после `f652427`); проверка этого — разовый
  скрипт из сессии, его надо сделать постоянным;
- известные нарушители размещения тестов: `src/core/application/casting/castOptions.test.ts`
  импортирует `@/ui/shared/model/actionTraits` и `@/ui/features/filter-spells/model/filters`;
  `src/ui/widgets/blood-magic-wizard/ui/BloodMagicWizard.test.tsx` не импортирует свой модуль,
  а рендерит `PlayShell` под псевдонимом `PlayScreen`.

## Правила для всех задач

Они же в `HANDOFF.md`, повторены, потому что план исполняют отдельные агенты по одной задаче:

- Перед задачей прочитать `CLAUDE.md`, докстринги `scripts/check-docs.py` и
  `scripts/check-layers.py` — новые скрипты пишутся в их стиле: python3, докстринг-спека в шапке
  (что проверяется и почему), список `errors`, русский вывод, выход 1 при ошибках.
- **Докстринг скрипта — его спека.** Отдельного FR для скриптов не заводится (прецедент —
  check-layers). Правило, которое скрипт стережёт, при этом обязано быть записано в своём
  документе `docs/…` — если его там нет, дописать тем же коммитом.
- **Базлайнов не заводить.** Находка чинится, а не легализуется. Единственная форма исключения —
  явный allowlist-словарь в самом скрипте (образец — `ALLOWED_CONTEXT_EDGES`), и **каждая запись
  в нём несёт комментарий-обоснование**. Запись без обоснования — ошибка ревью.
- Порядок внутри задачи: сначала написать проверку и прогнать → получить список находок →
  чинить находки отдельными коммитами (по одной мысли) → последним коммитом убедиться, что
  проверка зелёная, и подключить её в `package.json`.
- Перед завершением задачи полный прогон, всё зелёное:
  `npm run check:docs && npm run check:layers && npm run typecheck && npm run test:coverage && npm run build`
  плюс новые `check:*` этой и предыдущих задач. Задачи, трогающие `src/ui/**`, гоняют и
  `npm run test:e2e` (19 прогонов).
- Покрытие 100 % — не снижать. Удалённый код уносит свои тесты с собой; перенесённый — переносит.
- Имена в коде — только из `docs/glossary.md`. Сообщения коммитов английские, «wip» запрещён.
- Если задача не даётся — откатить рабочие правки, ничего не вливать, записать причину в раздел
  задачи в этом файле и остановиться.

## Задача 1 — тесты на своём месте (расширить `scripts/check-layers.py`)

**Проблемы:** прогон ядра зависел от интерфейса; файл `PlayScreen.test.tsx` рендерил `PlayShell`
под псевдонимом; слайс-призрак `screens/play/` состоял из одних тестов; виджеты назывались
экранами.

**Правит:** `scripts/check-layers.py` (докстринг + четыре новых правила), затем находки.

Сейчас `check_imports` выходит на `".test." in path.name` — тесты не проверяются вовсе. Завести
для них **собственный** набор правил (слои они собирать вправе, но не любые):

1. **Тест ядра не знает про интерфейс.** Файл `src/core/**/*.test.*` не импортирует `@/ui/**` и
   `@/app/**`. Известный нарушитель — `castOptions.test.ts`: блоки, проверяющие `traitsOf`,
   `filterSpells` и прочее из `ui/`, вернуть в тестовый файл владельца
   (`src/ui/shared/model/spellList.test.ts` или `src/ui/features/filter-spells/…`); проверки
   самих `castOptions`/`slotPriceOf`/`castableWithinTurn` остаются в ядре без ui-импортов.
2. **Тест импортирует свой предмет.** `Foo.test.ts(x)` обязан импортировать модуль `Foo` из
   своего каталога (`./Foo` или полный `@/…/Foo`). Нарушитель — `BloodMagicWizard.test.tsx`:
   он проходит мастер через оболочку. Честный минимальный фикс — рендерить `GameScreen` (строка
   «Магия крови» принадлежит ему) и переместить файл в `src/ui/screens/game/ui/BloodExchange.test.tsx`,
   либо переписать на рендер самого `BloodMagicWizard` с прямыми пропсами. Выбрать то, что меньше
   теряет: инвариант FR-022/FR-177 «до подтверждения состояние не тронуто» требует настоящих
   сторов — значит вариант с `GameScreen`. Строки «Проверка» задетых FR — тем же коммитом.
3. **Псевдоним предмета запрещён.** В тестовых файлах импорт вида `import { X as Y }` для
   компонентов/классов из `src/` — ошибка (ловит трюк `PlayShell as PlayScreen`). Разрешить
   псевдонимы для типов и для конфликтов имён из **разных** модулей — по allowlist при
   необходимости.
4. **Слайс без реализации и имя не по слою.** Каталог-слайс в `src/ui/**`, содержащий только
   `*.test.*`, — ошибка. Идентификатор с суффиксом `Screen` (по `export (function|const) \w+Screen`)
   разрешён только в `src/ui/screens/**` — правило имени записано в глоссарии
   (строка «Разметка экрана»).

**Приёмка:** `npm run check:layers` зелёный; правила описаны в докстринге; `docs/quality.md`
(раздел о стратегии тестирования) получает абзац «тест живёт рядом с предметом и импортирует его».

## Задача 2 — спека↔код: названная проверка существует (расширить `scripts/check-docs.py`)

**Проблемы:** девять строк «Проверка» указывали на умершие имена тестов; семь e2e не принадлежали
ни одному требованию; статус обещал проверку, которой не было.

**Правит:** `scripts/check-docs.py`, затем находки (сейчас их ноль — задача почти чисто
инфраструктурная).

Три новых правила (номера 9–11 докстринга):

1. **Каждое названное имя существует.** Из всех документов собрать пары
   `(unit|интеграционный|компонентный|E2E) \`имя\`` из строк `**Проверка:**` — учесть, что имя
   **переносится на следующую строку** (нормализовать пробелы и переводы строк перед сравнением;
   это была реальная ошибка в ручном проходе). Имя обязано встретиться подстрокой хотя бы в одном
   файле `src/**` или `e2e/**`. Прототип алгоритма проверен в сессии: 187 имён, 0 промахов.
   Скрипт уже читает `src/` для глоссария — читать теми же средствами.
2. **Каждый e2e-прогон назван требованием.** Все `test("…")` из `e2e/*.spec.ts` обязаны
   встречаться в `docs/**`. Для unit/компонентных обратную проверку **не делать** — шум.
3. **Статус не обещает пустого.** `Готово`/`Проверено` при `**Проверка:** —` — ошибка
   (`Отложено`, `Отменено`, `План`, `В работе` — можно).

**Приёмка:** `npm run check:docs` зелёный; правило «строка Проверка называет живой прогон»
записано в `CLAUDE.md` не нужно — оно уже следует из «Спека — источник истины», достаточно
докстринга.

**Зависимость:** задача 3 удаляет тесты — эта проверка обязана существовать **до** неё, чтобы
удаление теста с именем из спеки сразу краснело.

## Задача 3 — мёртвые экспорты ядра (новый `scripts/check-dead-code.py`)

**Проблемы:** `exchangeHitPoints`, `regenerationApplies`, `sunSaveDc` и др. годами жили, покрытые
только собственными тестами; поле `activeEffect.type` писалось и нигде не читалось.

**Правит:** новый скрипт + `package.json` (`"check:dead"`), затем ~102 находки по контекстам.

**Семантика проверки.** Для каждого файла `src/core/**/*.ts` (кроме `*.test.*`) собрать экспорты:
`export (async )?(function|const|class|type|interface|enum) ИМЯ` и реэкспорты
`export { ИМЯ } from`, `export type { ИМЯ }`. Собрать карту импортов по всем не-тестовым файлам
`src/**` и `e2e/**`: `import { A, B as C } from "@/путь"`, `import type {…}`, реэкспорты.
Экспорт без единого не-тестового импортёра — ошибка. Матчить **по паре (путь, имя)**, а не по
слову: одноимённые символы в разных модулях не должны прикрывать друг друга (мой быстрый замер
словом даёт те же 102 — но скрипту жить дольше замера).

Allowlist `ALLOWED_TEST_ONLY: set[tuple[str, str]]` — с комментарием на каждую запись. Ожидаемые
кандидаты (проверить, не записывать вслепую): `availability.ts: ALL_TURN_RESOURCES` — канонические
признаки хода, фикстура десятков прогонов; `repositoryContract.ts: describeParsingContract` —
общий контракт двух реализаций хранилища (он и есть набор тестов, лежащий обычным модулем).

**Дерево решений для каждой находки** (в этом порядке):

1. Символ используется в **своём файле** → снять только слово `export`. Так закроется большинство
   подсхем (`hitPointsSchema`, `arcanaStateSchema`, …: они складываются в `*_FIELDS` рядом).
   Если собственный тест импортировал подсхему — перенацелить прогон на экспортируемую
   поверхность (`*_FIELDS`, собственную схему контекста), а не сохранять export ради теста.
2. Символ не используется нигде, включая свой файл, кроме своих тестов → удалить символ **вместе
   с его тестами**. `check:docs` из задачи 2 поймает осиротевшие строки «Проверка» — обновить их
   тем же коммитом (живой прогон или честный статус).
3. Символ используется только тестами **других** модулей → это фикстура или тест не за своей
   дверью. Либо перенести проверку к владельцу символа, либо дать тесту собственную фикстуру,
   либо — если символ действительно общий канон — запись в allowlist с обоснованием.
4. Тип, который является публичным контрактом функции (возвращаемый/параметр экспортируемой
   живой функции), но никем не именуется → снять `export` (вывод типов доступен через
   `ReturnType`/`Parameters`, а понадобится имя — вернут экспорт осознанно).

Чинить **по контекстам, по коммиту на контекст** (arcana, vitality, character, catalog, effects,
equipment, spellbook, sheet, application, infrastructure) — diff читается, откат дешёвый.

**Приёмка:** `npm run check:dead` зелёный; покрытие 100 % держится; в докстринге записано, что
проверка стережёт и почему типы проверяются наравне со значениями.

## Задача 4 — правила не в UI и дубли строк (новый `scripts/check-rules.py`)

**Проблемы:** «очки × тариф» в четырёх местах; «Берётся после короткого отдыха», набранное дважды;
литерал «зм» мимо таблицы валют; «d6» строкой; лестница 0…6 в компоненте.

**Правит:** новый скрипт + `package.json` (`"check:rules"`), затем находки.

Три правила:

1. **Дубль русского литерала.** Строковый литерал (`"…"` или `` `…` `` без подстановок)
   ≥16 символов с кириллицей, встречающийся в ≥2 не-тестовых файлах, — ошибка. Сейчас 9 находок;
   разбор:
   - «Кровавое колдовство не действует под прямым солнечным светом» (`vitality/vitality.ts` ×
     `casting/availability.ts`) — настоящая протечка: отказ агрегата и предупреждение обязаны
     быть одной строкой. Вынести фразы подавления в `vitality/blood.ts` рядом с
     `bloodMagicAvailable` (владелец — жизнеспособность), оба места читают оттуда.
   - «Реакция уже израсходована» — второе вхождение обязано читать `ACTION_SPENT_MESSAGES`.
   - «Проверьте условия», «Объявление и подтверждение» (шаги двух мастеров) — мастера намеренно
     звучат одинаково: вынести общие заголовки шагов в `ui/shared/ui/WizardShell` (это его
     словарь), а не в allowlist.
   - Остальные («Лимит подготовки», «Объявление мастеру», «Ко всем спасброскам», …) — разобрать
     по тому же принципу: одна строка — один владелец; allowlist только с обоснованием.
2. **Арифметика над состоянием в `src/ui/**`.** Ошибка, если в не-тестовом файле бинарные
   `+ - * / %` соседствуют с выражением состояния: паттерны
   `character\.[\w.]+\s*[-+*/%]`, `[-+*/%]\s*character\.[\w.]+`, то же для `\.remaining`,
   `\.maximum`, `\.current`, `\.level` на любом идентификаторе. Известные находки в
   `BloodMagicWizard.tsx` (`hitPoints.current - spent`, `spellPoints.remaining + points`,
   `Vitality.of(character).maximum - spent`) — это предпросмотр обмена; вынести в ядро функцией
   `bloodExchangePreview(points, character)` рядом с `bloodExchangeInstructions` в
   `casting/announcement.ts` (они уже считают эти же числа — не плодить второй вычислитель,
   а вернуть из одного места структуру для отображения). Прочие находки — по обзору: правило
   одно, «UI ничего не вычисляет по правилам игры» (`CLAUDE.md`, «Никаких протечек»).
3. **Запретные литералы вне владельца.** «зм», «см», «мм» в строках вне
   `core/shared/language.ts`; `d\d+` строкой в `src/ui/**` (размер кости приходит из состояния).
   Сейчас находок ноль — правило дешёвое, ставится на будущее.

**Приёмка:** `npm run check:rules` зелёный; e2e зелёные (задача трогает `ui/`).

## Задача 6 — DeepReadonly: мутацию запрещает компилятор

**Проблема:** «не изменять напрямую» держалось дисциплиной. Присваивание в поле состояния должно
не собираться.

**Правит:** `core/domain/shared/schema.ts` (или новый `readonly.ts` там же), типы `*State` /
`CharacterState`, тестовые фикстуры (~30–50 мест), `src/ui/app/testing/stores.tsx`.

1. Объявить в основе (`core/domain/shared/`) тип:
   `DeepReadonly<T>` — рекурсивный mapped type: массивы → `readonly`, объекты → все поля
   `readonly`, примитивы как есть. Записать в глоссарий строкой («Глубокая неизменяемость» /
   `DeepReadonly`).
2. `CharacterState` в `core/domain/assembly/state.ts` объявить как
   `DeepReadonly<z.infer<typeof characterStateSchema>>`. Затем — типы состояний контекстов
   (`VitalityState`, `ArcanaStateData`, `EffectsState`, `EquipmentData`, `SpellbookState`, поля
   персонажа), если tsc потребует согласованности. Внутренности `zod.parse` остаются
   изменяемыми — изменяемое присваивается readonly без каста.
3. Починить fallout. Ожидаемые классы:
   - **тестовые фикстуры** `const c = createThorne(); c.concentration = …` → собрать помощник
     `thorneWith(overrides: Partial<…>)` в `src/ui/app/testing/stores.tsx` (для ui-тестов) и
     локально в тестах ядра, либо спред на месте: `{ ...createThorne(), concentration: … }`.
     Механическая замена, по коммиту на пачку;
   - `structuredClone` + мутация → тот же спред;
