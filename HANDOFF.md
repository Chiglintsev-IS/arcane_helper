# План передачи: выравнивание структуры (2026-08-03)

Исполняется по одной задаче за сессию. Перед любой задачей прочитай `CLAUDE.md`,
`docs/domains/README.md` и названный в задаче ADR из `docs/decisions.md`. Правила для всех задач:

- Мелкие коммиты по одной мысли; код и спека — одним коммитом; сообщения на английском.
- Перед завершением полный прогон, всё зелёное:
  `npm run check:docs && npm run check:layers && npm run typecheck && npm run test:coverage && npm run build`
- Имена в коде — только из `docs/glossary.md`. Механику не выдумывать.
- Если задача не даётся (прогон красный и починить не выходит) — откатить рабочие правки, влить
  ничего, записать причину сюда в раздел задачи и остановиться.

## Что уже влито в main

  Сумка строго вещественная), ADR-0034 (оболочка + шесть экранов) — `docs/decisions.md`, в конце.
- `docs/domains/README.md` — новая карта: контекст `sheet`, явный список рёбер.
- `CLAUDE.md` — «Никаких протечек» расширен до шести правил.
- Стражи: `scripts/check-layers.py` проверяет рёбра контекстов по allowlist + `scripts/layer-baseline.json`
  (17 рёбер-долгов, 18 циклов — все вокруг общей схемы в `character`); новые рёбра/циклы — ошибка.
  `--write-baseline` перегенерирует. `scripts/check-docs.py` предупреждает об обрывках удалённых
  ссылок; флаг `--strict-link-remnants` делает их ошибками.

## Задача 0 — забрать worktree-потоки (первая, без неё никуда)

**Состояние на момент передачи:** док-поток уже влит в main (см. merge-коммиты), строгий режим
ссылок включён в `check:docs`. Не влит только код-поток «КД/Сумка/Лист» — он правит `src/` и
доменные документы. Пункты ниже применяй к нему:

1. `git worktree list` и `git branch --list 'worktree-agent-*'` — найди ветки (одна уже влита —
   стражи; смотри `git branch --merged main`).
2. Различай по содержимому: `git log <ветка> --oneline -- src/` — поток «КД/Сумка/Лист» правит
   `src/` и доменные документы; поток «чистка документации» — только `docs/`.
3. `git -C <путь-worktree> status` — если есть незакоммиченное, работа могла оборваться: дописанное
   осмысленно закоммить или отбрось явный мусор.
4. Сливай из основного каталога: сначала код-поток, полный прогон; затем док-поток, снова прогон.
   Конфликты вероятны в `docs/decisions.md` и `docs/glossary.md` — сохраняй смысл обеих правок.
5. После слияния код-потока: `python3 scripts/check-layers.py --write-baseline`, закоммить baseline
   (ребро `effects→sheet` должно уйти из долгов).
6. После слияния док-потока: в `package.json` добавь `--strict-link-remnants` к `check:docs` и
   убедись, что прогон зелёный. Прочитай финальный отчёт док-потока (последний коммит/ветка) — там
   список пропущенных им находок; они уходят в задачу 5.
7. Если код-поток пуст или сломан — задача 1 обязательна; иначе пропусти задачу 1.

## Задача 1 — только если код-поток не доехал: реализовать ADR-0033

Полное описание решения — ADR-0033. Контрольный список: `armorBase` у экипировки (необязательное,
целое > 0); `Equipment.armorClassBase` — геттер max(надетое, 10), хранимое поле и его правка умирают;
перебивка `overrides.armorClassBase`; `equipment.otherBonuses` переезжает в персонажа как
`miscBonuses`, правится с «Листа»; формула итога КД целиком в контексте `sheet` (эффекты отдают
вклады данными; ребро `effects→sheet` исчезает); «Поправка к КД» опознаётся типизированным
признаком, не строкой имени; миграция v3→v4 (база ≠ 10 → перебивка; прибавки → персонаж; эффект
поправки → признак; итоговые числа не сдвигаются — доказать тестом); Сумка: карточки «Доспех» и
«Прибавки без вещи» уходят, блок компонентов переезжает из «Привала»; «Лист»: блок КД с раскладкой
(база/Ловкость/вещи/прочие прибавки/перебивка); в шторке вещи у экипировки — поле «База КД доспеха».
Документы тем же коммитом: `equipment.md` (переписать «Модель»/«Инварианты» — они противоречат
FR-234..239), `character.md` (FR про прочие прибавки; из таблицы листа убрать чужие числа и
«Текущее здоровье»), `effects.md` (FR-093), `screens.md`, `glossary.md` (новые термины).

## Задача 2 — разрез PlayScreen на оболочку и шесть экранов (ADR-0034)

`src/ui/screens/play/ui/PlayScreen.tsx` (~900 строк) держит все шесть режимов, ~16 флагов шторок и
строковый протокол `openBlockId` («item:<id>», «ability:<имя>»…). Целевое:

1. Оболочка в `src/ui/app`: каркас, `ModeSwitcher`, выбор экрана по режиму, загрузка/ошибка сессии.
2. Шесть экранов в `src/ui/screens/*`: игра, книга, лист, сумка, привал, журнал. Экран владеет
   своими шторками и их состоянием: сумка — вещь/деньги; лист — кто он/уровень/характеристика/
   здоровье/прочие прибавки/отметки/перебивки; привал — долгий отдых/восстановление; игра — урон/
   реакции/поправка КД/ресурсы/кровь/мастер применения/концентрация; журнал — обмен данными.
3. Строковый протокол умирает: «что открыто» — типизированное значение (union) внутри экрана.
4. Общие блоки (шапка ресурсов, действующее, «Прошёл час») — общие компоненты, каждый экран
   монтирует их сам; таблица `SCREEN_PARTS` умирает вместе с контейнером.
5. Режим экрана — состояние интерфейса: убрать `screenMode` из доменной схемы (миграция: поле
   игнорируется при чтении старых сохранений; поднять версию экспорта), хранить в оболочке
   (localStorage), открытый режим переживает перезапуск.
6. Компонентные тесты переезжают за своими экранами; e2e остаётся зелёным; покрытие не падает.
   Документы: `screens.md` — правило «экран владеет своими шторками»; `glossary.md` — имена экранов.

## Задача 3 — живые дефекты правильности (по одному коммиту на пункт)

а) **Экономика хода — один источник.** Есть проекция журнала (`deriveTurnEconomy`/encounter) и
   кэш-флаги состояния (`turnTracking`, `reactionAvailable`); читатели уже разошлись (сотворение
   смотрит журнал, эффекты — флаг). Оставить проекцию; флаги убрать из схемы с миграцией.
б) **Правила сотворения — одни предикаты.** `checkAvailability` и `castSpell` кодируют одни правила
   дважды и разошлись (`overridable: false` обходится `allowAnyway`). Единые функции-предикаты,
   исполнение запрета там же, где объявлен.
в) **«Магическое восстановление — после короткого отдыха»** существует только задизейбленной
   кнопкой в UI (`CampActions`). Перенести проверку в use case/агрегат arcana: отказ с причиной.
г) **`exchangeBlood` принимает уже посчитанные хиты** (формула ×тариф — в UI). Принимать очки,
   считать хиты внутри core; тариф очков — владение arcana (перенести из `vitality/blood.ts`,
   ребро `arcana→vitality` уйдёт из baseline).

## Задача 4 — поднять правила из UI в core

`ui/shared/model/spellList.ts` и фильтры дублируют правила ядра (цена ритуала, «неподготовленный
ритуал уходит из боевого списка», готовность заклинания) — заменить вызовами core
(`bestCastPlan`/castOptions, `Spellbook`); id вещи из имени генерирует `Equipment.addItem`, а не
экран; сокращения монет («зм/см/мм») — одна таблица в `core/shared`, сейчас два словаря
(`useCases/equipment.ts` и `ui/entities/character/lib/labels.ts`); предпросмотры правок (хиты,
уровень) — доменные функции; дубль константы «10 без доспехов» в `migration.ts` — один экспорт
(если ещё жив после задачи 0/1).

## Задача 6 — разбор общей схемы состояния (ADR-0032, правило 5) — самая рискованная, последняя

`character/state.ts` держит подсхемы всех контекстов. Целевое: подсхема — в каталоге владельца
(`equipment/schema.ts`, `effects/schema.ts`, `vitality/schema.ts`, `arcana/schema.ts`,
`spellbook/schema.ts`); полную схему и корень `Character` собирает `src/core/domain/assembly`
(страж уже знает это имя: контексты не импортируют сборку); `withSheet(Partial<…>)` сузить до
явного набора листовых полей. После каждого переноса — прогон; в конце
`python3 scripts/check-layers.py --write-baseline`: цель — рёбра-долги и циклы к нулю. Если к нулю
не выходит — довести до минимума и перечислить остаток здесь.
