## Контекст

Прежний план — «стражи чистоты» — выполнен целиком (его текст — в истории git этого файла). Аудит
2026-08-04 (HEAD `6302159`) сверил архитектуру и стражей с шестью принципами: инварианты в одном
месте; логика только в ядре; целостность гарантирует агрегат; никто не валидирует чужое; сущность
целостна при создании и изменении; при обращении состояние гарантировано.

Вердикт: **устройство принципам соответствует, большинство держат скрипты, но на трёх путях они
держатся дисциплиной, а не механикой** — создание состояния (структурные типы, `of()` без разбора),
отмена (снимок проверяется только по ключам и спредится мимо корня) и разбор ввода в шторках
(`parseInt` решает за владельца). Плюс два пробела в самих правилах: CI гоняет не весь `verify`,
а заявленный запрет кастов и `any` не проверяется ничем.

Замеры на текущем коде (2026-08-04, HEAD `6302159`):

- **6 дублей фактов**: лимит подготовки ×3 (одно из мест мёртвое, другое врёт под перебивкой);
  «руны = бонусу мастерства» ×3 в application + число в фикстуре; действующий максимум хитов ×4;
  предел вещей ×2; база КД ×2; перебивка бонуса мастерства не доходит до КС/атаки заклинаний;
- **дыры целостности**: отмена мимо корня без проверки значений; `addItem` без валидации новой
  вещи; `withSheet` проверяет разобранное, а пишет сырое; «надето только экипировка» на пути правки
  живёт только в экране;
- **протечки UI**: `SheetScreen` сам собирает вход листа; `parseInt` в девяти шторках;
  `as Money`; два мёртвых импорта (`noUnusedLocals` выключен);
- **стражи**: в `ci.yml` нет `check:layers`/`check:dead`/`check:rules`, `check:docs` без
  `--strict-link-remnants`; скрипта против `as`/`any`/`@ts-ignore` нет; `any` сейчас 0, `as` ~15.

## Правила для всех задач

Повторены здесь, потому что план исполняют отдельные агенты по одной задаче:

- Перед задачей прочитать `CLAUDE.md`; для задач со скриптами — докстринги `scripts/check-docs.py`
  и `scripts/check-layers.py`: новые правила и скрипты пишутся в их стиле — python3, докстринг-спека
  в шапке, список `errors`, русский вывод, выход 1 при ошибках. **Докстринг скрипта — его спека.**
- **Номера строк в задачах — по HEAD `6302159`.** Перед правкой перепроверить поиском: соседняя
  задача могла сдвинуть файл.
- **Базлайнов не заводить.** Находка чинится, а не легализуется. Единственная форма исключения —
  allowlist-словарь в самом скрипте, и каждая запись несёт комментарий-обоснование.
- Порядок внутри задачи со стражем: сначала написать проверку и прогнать → получить находки →
  чинить отдельными коммитами (по одной мысли) → последним коммитом подключить в `package.json`.
- Перед завершением задачи — `npm run verify` зелёный; задачи, трогающие `src/ui/**`, гоняют
  `npm run verify:full`.
- Покрытие 100 % не снижать. Удалённый код уносит свои тесты с собой.
- Спека правится тем же коммитом, что и поведение; строки «**Проверка:**» называют живые прогоны
  (`npm run check:docs` это стережёт).
- Имена в коде — только из `docs/glossary.md`; новое имя — новая строка глоссария тем же коммитом.
- Сообщения коммитов английские, «wip» запрещён.
- Если задача не даётся — откатить рабочие правки, ничего не вливать, записать причину в раздел
  задачи в этом файле и остановиться.

### Задача 12 — шторки отдают набранное владельцу: `Number`, не `parseInt`; без `as` *(после задач 9 и 11)*

**Проблема:** девять шторок нормализуют ввод сами: `Number.parseInt("12.5")` молча даёт 12,

через `Number`, прибавки через `parseInt`). Заодно: `MoneySheet.tsx:46` собирает деньги через
`as Money` — единственный каст к доменному типу в `ui/`, скрывающий неполноту (умолчание схемы
молча допишет ноль); в `ItemSheet.tsx:6` и `MoneySheet.tsx:6` — мёртвый импорт

**Правит** (все — `src/ui/features/edit-character-sheet/ui/`): `HealthSheet.tsx:25-26`,

## Что план сознательно не делает

- **Не вводит branded/nominal-типы.** Они закрыли бы сборку состояния литералом на уровне
  компилятора, но ценой сквозного рефакторинга всех типов состояния. Реальные пути обхода закрывают
  задачи 7, 10, 12 и 14 — дешевле. Вернуться к вопросу, если обходы продолжат появляться.
- **Не вводит ESLint** — решение прежнего плана в силе: tsc плюс точечные python-стражи.
- **Не замораживает объекты в рантайме** (`Object.freeze`): неизменяемость держит компилятор
  (`DeepReadonly`), а касты, которыми только и можно мутировать мимо него, закрывает задача 14.
- **Не ставит блочных запретов** (числовые литералы, дубли латиницы) — шум; точечные правила
  добавляются по мере пойманных классов.

   рядом видно значение по формуле;
4. написать `const broken = state as unknown` в любом модуле — `npm run check:implicit` красный;
5. открыть прогон Actions этого дня — в логе виден каждый `check:*` из `verify`.
