# План: слои вместо перебивок

Рабочий план, удаляется по завершении. Постоянные дома у фактов: архитектурные требования —
`docs/architecture.md`, раздел «Требования к устройству»; решения — `docs/decisions.md` и
`docs/agreements.md` после З0; правила величин — `docs/domains/sheet.md` после З0. Здесь — цель,
модель до её переезда в спеку и задачи с зависимостями.

---

## 1. Цель

Сегодня отклонение от базы записано тремя способами с тремя математиками: `overrides` у персонажа,
`miscBonuses` у персонажа, `armorClassEffect` у заклинания. Перебивка не переносится (перебитая
Внимательность не двигает спасбросок Мудрости), формулы правил знают про вещи (`itemBonus`
параметром), у КД собственный движок слоёв, который заново собирает лист и руками дедуплицирует
вклады.

**Признак готовности:** в состоянии нет ни одного готового производного числа; любое отклонение —
вклад единой формы; КД считается тем же кодом, что пассивное восприятие; лист не импортирует ни
снаряжение, ни вещи, ни каталог.

Рабочее дерево уже посреди этой правки и не собирается: `overrides` и `miscBonuses` сняты со схемы
персонажа, а лист их ещё читает. Дерево впервые соберётся на З4 — до неё ветка не вливается.

---

## 2. Принятые решения

Развилки закрыты в обсуждении 2026-08-08; в З0 они становятся записями у своих владельцев.

1. **База хранится, слои снимаются.** Критерий: есть игровое окончание — эффект; нет — правка базы,
   переход, обратимый журналом. Повышение уровня — переход, не эффект.
2. **Постоянное принадлежит персонажу.** Раса, дар, назначение мастера без срока — постоянные
   вклады, поле персонажа; правятся с «Листа», обратимы журналом. В массиве эффектов постоянного
   нет: у эффекта есть окончание.
3. **Двух назначений на величину не бывает.** Единственность — инвариант владельца, второе
   отклоняется с причиной словами; движок конфликтов не разрешает и максимум не выбирает — тихий
   выбор решал бы за игрока. Выбор выгодного из применимых способов счёта — правило игры, считается
   молча.
4. **Данные у вещи, правило у величины.** Вещь несёт факты о себе (база доспеха, категория);
   формулу — включая предел Ловкости по категории — владеет модуль защиты. Правило меняется без
   правки вещей, вещь заводится без знания формул.
5. **`overrides` и `miscBonuses` умирают.** Перебивка → постоянное назначение, прочие прибавки →
   постоянная прибавка; приведение сохранений не меняет ни одного действующего числа.

## 3. Модель (до переезда в спеку на З0)

**Словарь величин** — `StatId` и три вида вклада — живёт в общем ядре (`shared/`), как словарь
монет: его знают все контексты, он не знает никого. Величины: `armorClass`, `spellSaveDc`,
`spellAttackModifier`, `initiative`, `passivePerception`, `preparedLimit`, `proficiencyBonus`,
`speed`, `ability:*`, `save:*`, `skill:*`. Цена: новая величина трогает два места — словарь и свой
модуль; иначе внешний контекст не назвал бы цель вклада, не импортируя лист.

**У величины нет базы.** Величина определена набором способов счёта и допустимым диапазоном.
Способ — формула с условием применимости; действует применимый с наибольшим посчитанным итогом.
Условие проверяется по составу принесённых вкладов, а не запросом состояния: способ несёт признак
рода («от доспеха»), «Доспехи мага» применимы, когда способа с признаком «доспех» не принесли.
Диапазон (1..30 у характеристики) — свойство величины, применяется в конце счёта.

**Три вида вклада:** способ счёта (max среди применимых), прибавка (сумма), назначение
(единственно, побеждает всё). Итог: `диапазон(назначение ?? max(способы) + Σ прибавки)`. Порядок
вкладов на итог не влияет. Источника во вкладе нет: движок параметричен по нему — принимает пары
«источник + вклад», возвращает разбор с тем же источником, не заглянув внутрь. Дедупликация
повторного заклинания — дело доски эффектов (`spellId`), не движка.

**Цикл невыразим** (три уровня, ни один не заменяет другой):

| Уровень | Что закрывает | Чем удерживается |
|---|---|---|
| Модули | величина зависит от величины | запрет циклов импорта, `check:layers` |
| Значения в модуле | то же в мелком | порядок объявления, компилятор |
| Данные каталога | вклад читает свою цель | типизированный читатель, разбор каталога |

Модули величин — по ответственности, и разбиение ациклично само: характеристики (корни) ← владение
← проверки, числа заклинателя ← защита, инициатива. Если разбиение по ответственности даёт цикл —
неверна граница, а не граф. Честно циклическое правило разрывается застывшим числом на момент
применения. Величина строится из объектов своих зависимостей, не по имени: цикл = «использовано до
объявления», ошибка компиляции. Карту «имя → величина» собирает сборщик, которого не знает ни один
модуль.

**Кто отдаёт вклады:** персонаж — корни графа и постоянные вклады; снаряжение — данные надетого;
каталог — вклады заклинания; эффекты — копии вкладов действующего с окончанием; лист — сток, только
считает, вклады получает параметром от сценария. Заклинание и зелье приходят неразличимыми: в
контракте нет поля «кто прислал».

**Разбор и предпросмотр.** Резолв возвращает число и вклады с источниками — `armorClassParts` с его
особыми полями исчезает, у всех величин один вид. «Что будет, если» — резолв с добавленным вкладом:
чистая функция, инвариант «до подтверждения состояние не меняется» выполняется устройством.

## 4. Задачи

Зависимости названы; всё, что их не имеет между собой, идёт одновременно. Пересечение файлов
разводится worktree.

### З0 — Спека

**Зависит:** ничего.
**Правит:**
- `docs/decisions.md` — ADR: аппарат вкладов (способы счёта вместо базы, три вида вклада, движок
  без источника, невыразимость цикла). Формулируется без игровых слов — правило переживает смену
  предметной области.
- `docs/agreements.md` — запись: перебивка умирает, её место занимает постоянный вклад персонажа;
  конфликт назначений разрешает игрок (решения №2, №3, №5).
- `docs/domains/sheet.md` — правила: способы счёта КД с условиями, диапазоны, свёртка. Один раз, у
  владельца.
- `docs/domains/character.md` — постоянные вклады; `docs/domains/effects.md` — эффект несёт вклады,
  постоянного среди эффектов нет; `docs/domains/equipment.md`, `docs/domains/items.md` — данные
  доспеха у вещи.
- `docs/glossary.md` — Величина, Способ счёта, Прибавка, Назначение, Постоянный вклад, Разбор;
  «Перебивка» → `Отменено`.
**Проверка:** `npm run check:docs`.

### З1 — Словарь величин и движок

**Зависит:** З0.
**Заводит:** `src/core/domain/shared/stats.ts` — `STAT_IDS`, `StatId`, три вида вклада, без поля
источника.
**Заводит:** `src/core/domain/sheet/resolve.ts` — свёртка, параметричная по источнику; разбор.
**Заводит:** `src/core/domain/sheet/stats/` — модуль на ответственность: характеристики, владение,
проверки, числа заклинателя, защита, инициатива; построение в порядке зависимости, закрытый
конструктор, карту собирает сборщик.
**Правит:** `scripts/check-layers.py` — запрет циклов импорта внутри контекста.
**Проверка:** `resolve.test.ts` — порядок вкладов не влияет; назначение побеждает; из применимых
способов действует наибольший по итогу; диапазон приводит. `stats.test.ts` — назначение на
характеристику протекает в навык и спасбросок. Файл-образец, который обязан не собираться: вклад к
КД, читающий КД.

## 5. Порядок и параллельность

```
З0 ──► З1 ──┬─► З2 ──┬─► З4 ──► З5 ──┬─► З6 ──► З7 ──► З8
            └─► З3 ──┘               │
                └────────────────────┘ (З6 ждёт и З3)
```

Критический путь: З0 → З1 → З2/З3 → З4. После З4 дерево собирается и вливается; З5–З8 идут поверх
влитого отдельными коммитами — по коммиту на задачу.
